# Native presentation differences

Component properties of mod-built native controls were captured at runtime on game build 26335745 at 2560 x 1440 and canvas scale 1, beside the native Map Editor window and the native Company window. Window chrome, filter field, segments, selected and unselected outline rows, the H3 heading, footnote text, enabled and disabled compact buttons, rules, scroll bars, tab toggles, section headings, field rows and input fields have the same sprites, fonts, sizes, colours and state colours as their native counterparts. A disabled product button has the native disabled tint (0.784, 0.784, 0.784, 0.502) and text alpha 0.5, as native Undo, Redo and Save have. The tint applies to the button's frame image through the same ColorTint transition on both sides, so a disabled frame dims as the native one does; this was read from component values, not from rendered pixels. Input field labels use the native `<style=FieldLabel>` and numbers in a field are right-aligned, as `DtoInspectorPanel.AddAxisField` and `InspectorField.AlignNumeric` build them.

Those captures were taken of the previous arrangement of the same controls. [Capture of the layout's elements](#capture-of-the-layouts-elements) holds the capture of the current layout, element by element.

These differences from native presentation remain, each with its reason:

Panel status colours are the native Map Editor's: problem text `#FF8080`, changed `#E8A33D`, added or completed `#7FB86B`. The proposed-target blue `#4DCCFF` is the native switch gizmo blue (0.3, 0.8, 1). In the world, the inspected object's frame uses the native selection gold (1, 0.8, 0); amber is a panel colour only, so gold and amber never share a surface.

Not captured: the world colours; a native numeric axis field; the panel's own `+` row marker and `+ ADDED` badge, which no supported operation can produce yet; the native outline row's trailing ` *`, whose row was cut off at the Map Editor's width in the comparison screenshot; and the properties listed as open under the capture table.

## Tab widths

The tab strip is the native `TabView`: `FinishedAddingTabs` gives each tab the share of the strip that its label has of the summed label widths. The Company window shows the rule: its widest tab, Equipment at 173 of 880, is 1.9 times as wide as its narrowest, Loads at 90. The product's four tabs, Object, Placement, Connections and Changes, follow the same rule; their widths are not captured yet.

Properties a capture cannot give stay open with their reason:

- The hover and pressed look of a button: the probe reads component properties of a control at rest. Run 15 has close-ups of the pointer resting on a product button and on a native one; no colour values were read from them.
- The tooltip's place and delay: the tooltip is one native object for every control, so a product tooltip is that object; only close-ups of a product and a native tooltip compare where it opens.
- The font of world labels: they are drawn outside the canvas, so the capture has no node for them. A native map label is Montserrat-Light SDF 16 in `#FFFFFF`; which font the world label renders in was not established.
- Drag behaviour of the divider and of the window's resize grip: behaviour, not a property; the rectangle rows of the native protocol cover it.
