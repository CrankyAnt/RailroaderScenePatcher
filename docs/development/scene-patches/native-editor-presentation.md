# Present editor feature content

`PatcherBehaviour.DrawWindow` in `EditorLayout.cs` builds Inspector mode: the outliner column beside the inspector column with a draggable divider between them. The command band is split at that divider: each column starts with its own band (`DrawLeftBand`, `DrawRightBand`), so each band is as wide as its column wherever the divider stands. `NativeEditorPresentation` owns the entry icon, the visible window, its placement, refresh scheduling and disposal. The patcher's state for a world outlives a world unload; the window does not. `PatcherBehaviour.EndAttempt` disposes the presentation with its entry icon and title-bar help button and ends the requests that waited on the scene, and `Attach` builds a new presentation when the next editor appears. `BeginAttempt` starts the panel's own state over for the new load attempt: the inventory, what was read and compared, the messages and any open form. Keep the feature's operation and error handling in its existing owner.

Every region has a fixed height or scrolls inside its own rectangle, so showing or hiding text or feedback moves no other control. Keep that property when adding content:

- Give a row a fixed height (`Height`) and a one-line text an ellipsis (`Line`), with the complete text in its tooltip.
- Never show or hide a control on a state change. Keep it in place and disable it with the reason in its tooltip.
- Put text of varying length inside a tab body, the session details or a help view, which scroll.

Add feature content to the place its meaning names:

- What the object is, its enabled state and what was detected about it: `DrawObject`.
- A way to put the object somewhere: a mode of `DrawPlacement`, with its fields in the body.
- A binding or another relationship of the object, such as Track binding or a crossing operation: a section of `DrawConnections`.
- What the active MapMod changes on the object and what that change still awaits: `DrawChanges`.
- A command for the inspected object or the world: `DrawRightBand`, which holds Select in world, Focus and Copy ID and ends with Details. A status of the session: a lamp in `DrawLeftBand`, beside Refresh. The first lamp reads Stale when the inventory snapshot no longer matches the scene or when the supplied definitions changed, each through something the panel did not do itself. `SuppliedDefinitions` holds the patch documents the last refresh read and compares the documents on disk with them every two seconds: a document edited, added or removed outside the editor marks them stale until Refresh. The patcher's own Save does not: `ActiveStorage.WritePatchDocument` reports the text it wrote (`PackDocuments.Written`), and that text becomes what later comparisons expect. State that belongs to the session and not to one object goes into `DrawSession`, which Details opens.

The decisions of the band that need no game live in `CommandBand.cs`, which the core tests compile: a status lamp's word, colour and reserved word, whether the lamp words fit the left band, why a command is disabled, the markers of an outliner row and the state-line badges. A lamp is a round image and a word without a frame, both in the lamp's colour; it has no button component, and its tooltip gives the reason. The word's rectangle has a fixed width that holds the lamp's longer word (`CommandBand.InventoryWord`, `CommandBand.SaveWord`), so the other word takes its place without moving anything. The band's widths are constants in `CommandBand`, and whether the words fit is decided from them before the band is built (`CommandBand.WordsFit`): a text measured while the band was being built, before its first layout, gave widths under which the words never showed. Refresh and both lamps with their words need 251 units, the three items and the row's three spacings, and the outliner is never narrower than 252; each lamp also keeps its own width, so a row short of room cannot pull it towards Refresh. When a band cannot hold them, each lamp keeps its dot. The tooltip sits on the dot and on the word themselves, is titled with the state word and starts its text with it (`CommandBand.LampTooltip`). The game shows the tooltip of the first object under the pointer that is on the UI layer (`GameInput.IsMouseOverUI`): an object the mod creates itself, as the dot is, must be on that layer, because a stack the builder makes is on the default layer and an object that takes its parent's layer is skipped. A disabled command stays in place with its reason: Select in world only while a world choice is pending, Focus and Copy ID only when nothing is inspected. The object name's row keeps 150 units free at its right end, under Details, for the Inspector and Guided switch.

An outliner row carries `!`, `*` and `+` before its name (`CommandBand.RowMarkers`): the native outline appends ` *` and ` +`, and the panel puts them first so that a name that is cut off keeps them. The state line shows the native Map Editor's badges `* CHANGED` and `+ ADDED`, bold, in capitals, at 90 percent of the line's size (`CommandBand.Badge`). `*` never means unsaved, and the window's title carries no `*`: unsaved work shows only in the Saved or Unsaved lamp. No supported operation adds a scene object yet, so `IsAdded` answers no for every entry.

The actions of a tab live in the footer, not in the tab body. A native compact button sizes itself to its text through its content size fitter; a footer slot turns that fitter off so the button takes the width of its cell, and another label changes no rectangle. The four cells are 80 units wide from the left and do not stretch with the divider or the window; a slot label has at most seven characters. Keep tooltips of controls at the bottom edge to one line: the native tooltip opens below the pointer. `Slots` returns the four action slots for the open tab and mode: a label of at most eight characters, a tooltip, the reason the action cannot run now, or null, and the action. A pending world choice and an active gizmo take the slots over. Above the slots the footer has one message area of fixed height, six lines, so nothing outside it moves. It is a native scroll view of that height: its entries stack from the top without gaps, each as high as its wrapped text (`MessageSlot`), the viewport cuts off what does not fit, and the rest is reached by scrolling. Do not replace it by a stack of fixed height: a layout group that has less room than its entries need squeezes them below their text, and the text of one entry is drawn over the next. The first line says what the window waits for or why the open tab cannot edit, when there is such a state: a pending world choice with its candidate, the gizmo hint, a prepared snap, a confirmed identity, or `EditBlock`. Below it come `EditFeedback.Messages`, newest first, the older ones dimmed. A result that is reported again moves to the top instead of being listed twice, so the success of a corrected action sits above the refusal it corrected. An action that only opens a form, such as Add detection, reports that, for the same reason, and the row is withdrawn when the form closes (`OpenedForm`, `EditFeedback.Withdraw`). A completed preview is a result as well, so it leads an earlier preview refusal. The text stops 4 units short of the area's right edge: the native scroll view lets its viewport run 3 units under its scroll bar. A follow-up is a consequence that arrives by itself after a result, such as terrain output after an activity edit; report it with `Follow`, which replaces the follow-up before it and never a result, so a row of follow-ups does not push the result out of the area, and report the result of an action the user selected with `Report`. Every line starts with its source in bold, one space before its text. A result's source is the place it was reported to, so name a place as the modder knows the action group: Placement, Enabled, Track binding. The session details list the last three messages in full. A tab switch changes `inspectorTab`, which is part of the content snapshot, so the footer follows the tab. An object without an editable binding names its own detected reason on the binding's slots and fields (`BindingUnavailable`), before the general reason it cannot be edited. The outliner width is stored in the game's preferences under the window's key, beside the bounds the native window saves there; nothing is written through Unity's `PlayerPrefs`, which is the registry key the user's normal play shares. After a world choice is cancelled nothing counts as confirmed (`SpatialSelection.Confirmed`). The Connections tab serves three structures with the same fields and slots where they apply: the track binding of a generic track marker, the binding of a crossing pad, whose section is titled Crossing pad binding and whose Detach slot is disabled with its reason, and the coverage of a crossing.

Each region has help in the `Help` table: an introduction, short terms and guide links. Each `?` sits in the region it explains, names its scope in its tooltip and shows `x` while its help is open (`HelpButton`); Reset layout is a window command and sits in the window help. The window's `?` stands in the title bar, directly left of the close button (`NativeEditorPresentation.AddTitleHelp`): a native compact button in the close button's parent, placed from the close button's rectangle. Its help says that it applies to the whole window and shows in place of the tab body. When the title bar cannot take it, `TitleHelpProblem` says why and the right band holds a `?` before Details. The three anchors at the bottom of the outliner stay in view while any help is open. Further, the `?` in the first row of a tab body shows that tab's help below that row, and the outliner's `?` replaces the outline list. The first row of a tab body also holds the tab's description. After the native tab strip is built, each tab title gets 8 units of padding and an ellipsis for a strip that is too narrow; the four titles are never renamed. Add a term when a feature needs explaining, in the tone of a native tooltip, and put a standing explanation in the panel only where an action needs it.

Status colors are the native Map Editor's: `#FF8080` for a problem or failure, `#E8A33D` for changed, stale or blocked, `#7FB86B` for completed or confirmed, and `#4DCCFF` for a proposed target. Use `Tint` with the constants `Red`, `Amber`, `Green` and `Blue`. World markings use the same meanings through `WorldSelectionOverlay`: gold frames the inspected object, one frame per object; blue marks the chosen candidate; green a confirmed relation; a red label rule marks only an object with a detected problem; other choices are neutral. Amber never appears in the world.

The outliner (`DrawOutliner`) holds a top row with the native filter field, its `?` and the Fit button beside the divider, then the All, Problems and Changed segments, a count line, the `AddOutlineView` rows under one folder per family and three anchors. A row's markers stand directly before its name and take room only on a row that has them, so the column's width goes to the names and the end of a long name can be cut off without losing a marker. A folder row starts with its count, followed directly by the family name. A name that repeats in its folder carries its parent, dimmed; an inactive object's name is italic. `InventoryPresentationState.Rows`, `Groups` and `FitWidth` decide which entries show, how they group and how wide the column becomes; `AuthoringSession.IsChanged` reads the document alone, so it can be asked for every row.

Use `PatcherBehaviour.Button` for a compact action that requests a content refresh after its callback. Use `Heading` for a heading in the native H3 style: it sets no height, so the line is as high as its own text, 23.2 like a native H3. A line with an ellipsis draws nothing when its rectangle is lower than its text line by any fraction, so do not give such a line a height below what the text needs. Use `PlainLabel` for scene and document text, `Field` for a named value, `FieldLabel` above an input field and `Section` for a group heading, which draws a rule above the native section header so that a heading differs from a field label. `ValueField` builds an input field, or the value as text of the same height without the input frame when the object cannot be edited now. `BindingFields` shows an observed line of the form `Marker id=...; type=...` as named values. `Breakable` lets a path wrap after a separator. `Field` shows the native field label above a left-aligned value; every tab uses this one form, so the same kind of element has the same size, weight and colour everywhere. A state that appears in more than one place has one markup constant, as `ChangedBadge` has for the state line and the Changes tab. Text from the scene passes through `Literal`, so it cannot act as markup.

The native window saves its bounds when the user moves or resizes it and when it is shown or closed. It is shown before the layout places it at its default position, so the presentation raises the window's own moved event after that placement (`SaveBounds`); the next editor session then restores the placed bounds instead of the window's initial top-left position. The presentation uses `WindowManager.CreateWindowWithComponent<ScenePatchWindow>`, the manager's window prefab and builder assets, and `BuilderWindowBase` panel ownership. Fields, headings, tabs, segments, scrolling and buttons use native builders. The constructor refuses to build when a builder asset the layout uses is missing. Native Save, Undo and Redo keep their existing owners. Existing prompts use the checked native modal factory in `Hooks`; new prompts must preserve their feature's cancellation, outstanding-work and session guards.

`PatcherBehaviour.Edit` queues the edit through `Queue`, which also serves every other request that needs an inspection token: the crossing coverage preview, preparing a snap after its target is confirmed, and starting the gizmo. No panel action except Refresh, and the first fill of an empty inventory, compares or discovers the whole scene in one frame. When the snapshot was compared since the last foreign change of the editor's history (`Compared`: a refresh or a completed pass under the current history value, at most two minutes ago), the request runs in the next frame. Otherwise the first message slot shows the action group with "Working..." while a stepped pass compares the whole scene, 8 milliseconds a frame. The patcher's own edits, Undo and Redo keep the snapshot compared (`OwnChange`), because their objects are observed again; no pass steps between such a change and that observation. No pass steps while a gizmo is active either: the pose of its target is the patcher's own preview, and its target is observed again when the gizmo ends, by a release or a cancellation. Escape cancels a pending world choice or an active gizmo through a transient handler of `UI.GameInput` and is consumed, so the pause menu stays closed. The idle comparison that informs the band takes a 2 millisecond step on every third frame, pauses five seconds after a pass, and starts at once at the edit's pace when the editor's history changes by something other than this patcher. One unit of a discovery, such as the search for all components, can still exceed a step's budget. When the pass ends the edit runs: refused when the pass found a difference or the editor's history changed meanwhile, otherwise applied behind its guard. A completed edit reports its result and calls `RefreshAfterEdit`, which observes the edited object and what belongs with it again two frames later. A change of the inspected object's terrain output is reported as a follow-up from `TerrainSnapshot`. Until that observation the inventory holds the object as it was before the edit, so an edit in between is refused as changed. Resolving a target walks down from the roots of its scene along the path (`BoardScene.LoadedAt`), so its cost follows the path and not the size of the scene. A closed window does no per-frame presentation work: the content snapshot that requests refreshes is computed only while the window is open. Keep work that searches the scene out of that snapshot. A value the panel reads every frame for the inspected object resolves its target once per observation, as `InspectedOutput` does for terrain output; every inspection, refresh and completed edit produces a new observation. The outstanding-work text is recomputed when the editor's change counts, the last Save or an incomplete operation change, and once a second.

Call `RequestRefresh` when external state changes the content. A refresh waits until native input fields lose focus and a left-button drag ends. The window itself does not scroll. Build a scrolling region with `NativeEditorPresentation.Scroll`, as each tab body does; the presentation retains the scrolled distance of the region built last during that refresh. Store field values in feature state as they change, before an action can read them. Use a separate native rebuildable section for live search results so typing does not rebuild the search field.

The entry is an icon among the native icons of the top-right strip: a clone of a native icon button with every native script removed, the native tooltip provider and the icon from `Icons/SceneWrench.png` beside the assembly, inserted after the last native icon so the strip's own layout places it. The sprite shows a square of the PNG centred on the drawing and sized so the drawing fills the button as the native icons fill theirs (`IconFrame`): the larger side of a native drawing covers 94 to 128 of its 128 pixels, 118 at the median. A PNG with uneven transparent margins therefore still sits centred and as large as its neighbours. It exists while a map editor is attached and is therefore absent in normal play. Replacing the PNG replaces the icon without a rebuild. When the strip cannot take the icon, a floating entry button replaces it and `EntryProblem` names the reason in the session details. For persistent feature feedback on the closed entry, call `SetEntryStatus(caption, reason)`; the tooltip reads the current values. The feature owns deriving and clearing that feedback.

Pass window and entry screen bounds to `InspectionInputBlocker.SetRegions`. Native controls own their raycasts. The blocker retains the separate native wheel-input boundary and the world-pick gate. World-space labels and marks remain in `SpatialSelection`.

Use `NativeEditorPresentation.WorldUiBounds` for world-mark clipping and pick exclusion. It reads current native window and visible graphic bounds, including the title, controls and entry, while excluding the invisible input boundary and full-screen event surfaces. Collecting them walks every UI graphic, so one collection serves a frame: the next use collects again while a pointer button is down, after this window is placed, shown or hidden, and otherwise at most ten times a second. Input-region synchronization runs before early input sampling and after native layout. A pick inside current UI bounds leaves pending offers unchanged.

The native close request clears owned input focus immediately. The feature close callback runs only from `OnShownDidChange(false)` after the native close transition. Do not invoke it again from the close request.

Create the presentation for an attached map editor and dispose it when that editor changes or the world unloads. Disposal clears owned keyboard focus, unsubscribes window callbacks, disposes the entry panel and deactivates the owned roots before destroying them. Do not register persistent custom-window definitions or leave callbacks referencing an old editor.

The native construction is internal game integration, compiled against Railroader build 26335745. Compilation and source inspection do not establish native appearance, input routing or cleanup at runtime. The integration journey must compare corresponding controls and states, measure window and chrome bounds at both required layouts, and replay the feature's behavior. Required unmeasured properties and unverified construction remain open acceptance evidence.

The window first opens below the native Map Editor window, with that window's left edge, as wide as the default width or that window, whichever is wider, down to the bottom of the screen. Native windows sit flush with the screen edges and each other, so the placement adds no margin or gap. When less than the minimum height remains there, it keeps its minimum height at the bottom of the screen and overlaps the lower part of the Map Editor window. The presentation keeps the divider's column within what the window allows on every frame, because the content is built before the window has its size and the window can be resized afterwards; the first open uses the default column width. A panel that was shown when the editor was left opens again, on the first tick: the owner builds the content through the presentation and holds it only after the constructor has returned. A placed window keeps its position and size, as native windows do: native UI that opens over it, chrome rebuilds and camera moves do not move or resize it. The native window persistence saves its bounds under the window identifier, and bounds saved in an earlier session win over the default. `ResetLayout` forgets them; the next layout after the button is released places the window at the default again. Layout places the window again only when it no longer lies within the screen. No controls move during a left-button press or drag.

The default size is 690 by 660 canvas units, wide enough for the three outliner filters beside the four tab titles and therefore wider than the Map Editor window; the minimum is 660 by 410, whose height fits below the Map Editor window on a 1080-high screen and whose width holds the outliner's minimum beside the inspector's and the command band's buttons and states at their own widths. The outliner column starts 252 wide, the width of its band with Refresh and both lamp words, is never narrower and leaves the inspector at least 350, which holds the four footer slots and the resize grip. A window too narrow for the stored width shows a narrower column without overwriting it. The divider between the columns is `ColumnDivider`, a mod-built drag handler on a native rule: the native builders have no splitter, and this control is the recorded exception to native construction. Its width and the Fit result are stored in the game's preferences. The native window saves its content size and, on restore, raises it to the configured minimum, which this window means for the whole window; `RestoreSavedSize` applies the saved content size again, unraised, so saved bounds come back exactly. When the window goes, `HideTooltip` sets the game's tooltip callout to transparent, so a tooltip of this window that showed when the editor was left does not stay on screen. While no bounds are saved, `PanelPlacement.Default` places the window: below the Map Editor window when at least 600 canvas units of height remain there, and otherwise at the top right of the screen, right-aligned below what occupies that corner, with the width it would have below the Map Editor window. `PanelPlacement.OccupiedBelow` finds that lower edge from the visible native UI in the window's column: the button strip and the status readout below it. Its height there is what remains below that edge, at most the default height of 660 or what remains below the Map Editor window, whichever is more, and never less than the minimum height.

`Scroll` adds the game's `ScrollRectSettingsApplicator` when the native scroll view lacks it, so the wheel step is the game's own, and gives the region a minimum height. A refresh restores the distance scrolled from the top of the tab body, clamped to the new content.

`EditFeedback.Inspecting` receives the inspected handle every frame and clears the last result when another object is inspected.

The measured properties of this layout beside their native counterparts, and the differences that remain, are in [native presentation differences](native-presentation-differences.md).
