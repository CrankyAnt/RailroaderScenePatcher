# Record the native fixed-placement journey

Traces captured outside an identified active world carry `sourceLifecycle: unassigned` and a null `sourceLoadId`. They emit as `unassigned-attempt-trace` and remain separate from active-world counts. A deliberate replay after observer readiness measures same-engine retries without silently attributing early callbacks to a later world.

This test-only mod records observations for the fixed-placement fixture. It does not install itself or start the game. Build it against the installed game assemblies, placing all build outputs outside the repository:

```powershell
dotnet build Tests/NativeObservation/NativeObservation.csproj -p:GameManaged='<Railroader_Data/Managed>' -p:BaseIntermediateOutputPath=C:/TMP/Issue39ObservationBuild/obj/ -p:OutputPath=C:/TMP/Issue39ObservationBuild/bin/
```

A later authorized test must install `NativeObservation.dll` and `Info.json` in `C:/TMP/RailroaderMapResearch/RuntimeHome/Mods/Issue39Observation`. The observer checks the sole `-homedir` argument and its mod directory before recording or exposing controls. It writes `Evidence/<loadId>/observations.jsonl` under that mod directory on any map in the isolated home, with the `world-ready` event and the attempt traces. Each row's `mapId` names the loaded map; `world-ready` also records `fixtureMap` and the patcher's `engineRuntimeId`, which `Tests/FixedPlacementJourney/Summarize-Attempts.ps1` takes as its `-EngineRuntimeId`. Snapshots, tile events, focus, replay and the trace-stage snapshots need active map `crankyant/fixed-placement-fixture-map`; on another map they record nothing, and a click on their buttons records an error. The observer creates a fresh load ID for each world load. Preserve the complete evidence directory with the corresponding build and fixture provenance.

Use the explicit baseline, after and restoration snapshot buttons at the intended phases. A successful snapshot contains one unique Sylva board in BushnellWhittier-MapManager, origin conversion, the T-47 marker and graph registrations, culler token and sphere, mask modifier descriptors and targets, and terrain pending/idle state. A `snapshot-error` means that phase is incomplete. `OnTileBuilt` events contain native map-coordinate bounds. JSONL rows carry schema and evidence kind, event sequence, load ID, frame, UTC, process ID, and SHA-256 hashes of the loaded Railroader, observer and patcher assemblies. Startup attempt traces can precede observer readiness; buffered rows retain their original `sourceFrame`, while their sequence identifies when they were written. Trace capture requires the patcher's debug option to be on. The patcher writes each `Attempt trace:` line as a debug line only while that option is on, and the observer reads those lines from the game's log. `Tests/FixedPlacementJourney/TestHome.ps1` installs `Tests/FixedPlacementJourney/DebugSettings.json` as `Mods/Issue39ScenePatcher/settings.json` in the test home, which starts the option on. The journey uses the normal patcher build, not a separate instrumented one. The observer does not patch native methods.

The replay button explicitly calls the current patcher application callback once and records whether the engine reference stayed the same. It is a diagnostic action, not a native world reload. The observer also takes snapshots on the mutation, applied, restore-request and restore-result trace stages while it is ready. Buffered startup traces cannot recover an earlier snapshot. Capture the baseline in an unmodified fixture session with the patcher engine loaded before generating the test scene patch file. The generator produces `Baseline.json`; copy it to the observer mod through the test-home preparation command. Its shape is `{ "schemaVersion": 1, "snapshot": <selected baseline JSON object> }`. On later loads the observer validates its identity and uses its board map position for both tree sample regions. It records the original process, load, graph, scene and board identities in `referenceSource`. An invalid file is reported in `referenceError` and `measurementErrors`; its presence disables baseline recapture. Snapshot methods do not set object placements, activity, hierarchy, graph registrations, masks or terrain. The explicit replay control can change targets through production application. Focus board and Focus T-47 move the native strategy camera and can trigger floating-origin movement. Snapshot labels are operator claims, not proof that application or restoration occurred. Compare state and trace events and inspect errors before drawing a conclusion. The probe was used in an isolated Railroader 0.6.2 build 26335745 journey. Snapshot labels alone remain insufficient evidence; compare the recorded placements, registrations and terrain state. Generated-tree samples count and hash native array entries within 20 m of the baseline position and baseline plus 5 m, and record the native handoff and loaded array relationships. They also record interpolated map height at each sample point. They do not inspect the complete heightmap or rendered pixels.

## Culling readout

The **Culling readout** window works on any map in the isolated home. It checks the sole `-homedir` argument and the observer's mod directory, not the fixture map. Enter the path of a group root, such as `World/Large Scenery/Whittier/Whittier Saw Mill`, and a label for the phase, then click **Culling readout**. Each click appends one row to `Evidence/culling/readout.jsonl` under the mod directory.

The **Collider readout** button in the same window uses the group path and pad marker ID already entered. It appends one row per `Collider` below the target to `Evidence/culling/colliders.jsonl` under the mod directory, including disabled colliders, or one `no-colliders` row when there are none. Each row carries the `event`, `index`, object `path`, component `type`, `enabled`, `isTrigger`, `activeSelf`, `activeInHierarchy`, the attached `rigidbody` (path, instance ID, `isKinematic`, or null), and world `bounds` as `center` and `size`, with the readout's `sequence`, `label` and `padMarkerId`. The window shows the readout number and the collider count.

A row holds the camera's map position and its distance to the group. For each simple, renderer and game-object culler in the group it holds the radius the scene gives it, the center and radius of the sphere it holds, and its visibility or culling state. For a simple culler it also names the handler on its culling group. For each own sphere of a moved part it holds the ID, the part, the center in map coordinates, the radius, whether it waits for a game culler, whether it shows the part, and the enabled state of the part's renderers. `gameObjectCullers` lists every game-object culler of the loaded scenes with the path of each object in its `gameObjects` list, and `handedOver` lists the objects the patcher took out of such a list for a moved part. The `activity` list gives `activeSelf`, `activeInHierarchy` and the patcher's desired value for the root and every object below it, up to 600 objects. An object between the root and a moved part with its own sphere also lists the components directly on it.
