# Present scene patch editing feature content

`PatcherBehaviour.DrawWindow` in `ScenePatcherLayout.cs` builds Inspector mode: the outliner column beside the inspector column with a draggable divider between them. The command band is split at that divider: each column starts with its own band (`DrawLeftBand`, `DrawRightBand`), so each band is as wide as its column wherever the divider stands. `NativePresentation` owns the entry icon, the visible window, its placement, refresh scheduling and disposal. The patcher's state for a world outlives a world unload; the window does not. `PatcherBehaviour.EndAttempt` disposes the presentation with its entry icon and title-bar help button and ends the requests that waited on the scene, and `Attach` builds a new presentation when the next native map editor appears. `BeginAttempt` starts the panel's own state over for the new load attempt: the inventory, what was read and compared, the messages and any open form. Keep the feature's operation and error handling in its existing owner.

Every region has a fixed height or scrolls inside its own rectangle, so showing or hiding text or feedback moves no other control. The footer message scroll rectangle reserves a fixed action row at its bottom in every state. The scroll rectangle includes the height of that row in addition to the message viewport. Version choice actions occupy that row outside the text viewport, so they do not scroll with messages. With automatic viewport expansion disabled, explicit stretch anchors give that viewport its available width, excluding the scrollbar and action strip. The native vertical layout then gives each message its wrapped text height. Keep that property when adding content:

- Give a row a fixed height (`Height`) and a one-line text an ellipsis (`Line`), with the complete text in its tooltip.
- Never show or hide a control on a state change. Keep it in place and disable it with the reason in its tooltip.
- Put text of varying length inside a tab body, the session details or a help view, which scroll.

Add feature content to the place its meaning names:

- What the object is, its enabled state and what was detected about it: `DrawObject`.
- A way to put the object somewhere: a mode of `DrawPlacement`, with its fields in the body.
- A binding or another relationship of the object, such as Track binding or a crossing operation: a section of `DrawConnections`.
- What the edited mod changes on the object and what that change still awaits: `DrawChanges`.
- A command for the inspected object or the world: `DrawRightBand`, which holds Select in world, Focus, Clear and Copy ID. Clear ends the inspection through `ClearInspection` and is disabled only when nothing is inspected and no world choice is pending (`CommandBand.Clear`). A window command, Session details or Reset layout, is an icon in the title bar. A status of the session: a lamp in `DrawLeftBand`, beside Refresh. The first lamp reads Stale when the inventory snapshot no longer matches the scene or when the supplied definitions changed, each through something the panel did not do itself. `SuppliedDefinitions` holds the scene patch files the last refresh read and compares the scene patch files on disk with them every two seconds: a scene patch file edited, added or removed outside scene patch editing marks them stale until Refresh. The patcher's own Save does not: `ModStorage.WriteScenePatchFile` reports the text it wrote once that text has replaced the file (`ModScenePatchFiles.Written`), and that text becomes what later comparisons expect. State that belongs to the session and not to one object goes into `DrawSession`, which the Session details icon in the title bar opens.

The decisions of the band that need no game live in `CommandBand.cs`, which the core tests compile: a status lamp's word, colour and reserved word, whether the lamp words fit the left band, why a command is disabled, the markers of an outliner row and the state-line badges. A tooltip of a control that cannot be used is only the reason after the one label `Unavailable:` (`CommandBand.Tooltip`): the description of what the control does applies only while it can be used, and the tooltip's title names the control; `CommandBand.Sentence` gives that reason, like the editing message (`CommandBand.EditReason`) and a binding that cannot be set, as one plain sentence without its own label such as `Not editable:` or `Track binding unavailable:`. The outliner lists the rows of each family, and of the Inspection only group, in the order of their names and then their paths (`InventoryPresentationState.Groups`). A lamp is a round image and a word without a frame, both in the lamp's colour; it has no button component, and its tooltip gives the reason. The word's rectangle has a fixed width that holds the lamp's longer word (`CommandBand.InventoryWord`, `CommandBand.SaveWord`), so the other word takes its place without moving anything. The band's widths are constants in `CommandBand`, and whether the words fit is decided from them before the band is built (`CommandBand.WordsFit`): a text measured while the band was being built, before its first layout, gave widths under which the words never showed. Refresh and both lamps with their words need 251 units, the three items and the row's three spacings, and the outliner is never narrower than 296; each lamp also keeps its own width, so a row short of room cannot pull it towards Refresh. When a band cannot hold them, each lamp keeps its dot. The tooltip sits on the dot and on the word themselves, is titled with the state word and starts its text with it (`CommandBand.LampTooltip`). The game shows the tooltip of the first object under the pointer that is on the UI layer (`GameInput.IsMouseOverUI`): an object the mod creates itself, as the dot is, must be on that layer, because a stack the builder makes is on the default layer and an object that takes its parent's layer is skipped. A disabled command stays in place with its reason: Select in world only while a world choice is pending, Focus and Copy ID only when nothing is inspected. The object's name takes its whole row and is cut only when the row is too short; its tooltip holds the full path. The Inspector and Guided segmented control occupies the right end of the row, and the name gives way to it when shown. The name has a LayoutElement with zero minimum and preferred width, flexible width 1 and layout priority 2, so its text cannot push the switch.

An outliner row carries `!`, `*` and `+` before its name (`CommandBand.RowMarkers`): the native outline appends ` *` and ` +`, and the panel puts them first so that a name that is cut off keeps them. The state line shows the native Map Editor's badges `* CHANGED` and `+ ADDED`, bold, in capitals, at 90 percent of the line's size (`CommandBand.Badge`). `*` never means unsaved, and the window's title carries no `*`: unsaved work shows only in the Saved or Unsaved lamp. No supported operation adds a scene object yet, so `IsAdded` answers no for every entry.

A control sits where its scope is. The actions of a tab stand in a pinned row at the bottom of its tab body (`Tab`, `TabActs`), below the scrolling part and inside the tab, with a gap of 8 units above the footer; the row has a fixed height and exists on every tab, so the scrolling part has the same rectangle whatever the tab shows. The footer is the same on every tab: the message area, then one row with the actions on the inspected object that belong to no tab, Remove modification and Recheck (`FooterActs`). Enable or Disable and Clear activity stay together on the Object tab, and Retry for terrain output on Changes. Both rows are drawn by `ActionRow`. Below the footer's row stands a spacer of 12 units (`CommandBand.GripClearance`): the native resize grip is 22 units high in the window's lower right corner, and the footer does not reach into it. A native compact button sizes itself to its text through its content size fitter, and every button of the panel keeps that size: its label and 6 units of padding on each side. Only a button whose label changes in place, such as Disable and Enable, gets the width of its widest label (`FitButton`), so the change moves no control. The rule and its call sites are under Shared rules below. Keep the description of a control at the bottom edge to one line: the native tooltip opens below the pointer. A disabled control keeps that description and adds its reason on a line that starts with "Unavailable:" (`CommandBand.Tooltip`), in the band and in the footer. An action slot is a label, a tooltip, the reason the action cannot run now, or null, the action, and optionally a longer tooltip title and the other label the button changes to. Name a control that takes something back by what it takes back: Clear activity, Clear binding, Clear circuit, Discard for a prepared snap, Remove modification. No tab holds a bare Clear. A slot does not carry the name of its mode: the Follow mode starts following with Start. The Gizmo mode has a Move and Rotate switch in the tab body, Move first (`gizmoTool`), disabled with its reason while a world choice is pending, and no action: the gizmo stands on the object while the mode is open (`ArmGizmo`), and choosing the other tool changes it at once (`GizmoController.SetMode`). A pending world choice takes the footer's row over with Confirm, Cancel, Focus and Details; a gizmo takes it only during a drag, with Cancel. A gizmo that merely stands leaves the row as it is. While a choice is pending, every control of the tab is disabled with that reason (`ChoiceBlock`); the fields stay as they are. The fourth slot of a pending choice is Details. It shows only the clicked candidate's identity and details, in the message area below the candidate line (`candidateDetails`), and is disabled until something was clicked (`CommandBand.CandidateDetailsReason`). It never opens the session details: two controls do not show the same thing, and the tab body is for tabs. The session details open from their title-bar icon alone, in a native builder window of their own (`SessionDetailsWindow`, `NativePresentation.ToggleDetails`), which the game saves under its own key, which opens beside the panel the first time and which closes with the panel. They hold only session state the panel shows nowhere else (`DrawSession`): the candidates of a world choice, the inventory status, the edited mod's scene patch file with a failed Save or incomplete operation, the supplied definitions and diagnostics. The messages and the reasons of the lamps are not repeated there. Their World choice section (`DrawChoice`) lists the other candidates, with Choose buttons labelled by `CommandBand.ChoiceLabel`, which leads with the name that tells a candidate from the others and cuts at the end. Starting a choice changes no view. The supported-edits text of an object of a supported family that cannot be edited reads "Not editable: " and its reason (`CommandBand.NotEditable`). That wording keeps clear of "Inspection only", which names the outliner's group of objects whose kind has no edit yet; such an object carries its reason in `SceneObservation.InspectionOnly` (`CommandBand.NotYetSupported`). The world marks the track the inspected object follows in green, as a confirmed relation, also during a pending choice: `MarkFollowed` reads the followed element from the scene patch file when the inspection or the native map editor's history changes, and `SpatialSelection.Followed` rebuilds its marking from the graph element a few times a second, after one lookup by ID. Above the slots the footer has one message area of fixed height, six lines, so nothing outside it moves. It is a native scroll view of that height: its entries stack from the top without gaps, each as high as its wrapped text (`MessageSlot`), the viewport cuts off what does not fit, and the rest is reached by scrolling. Do not replace it by a stack of fixed height: a layout group that has less room than its entries need squeezes them below their text, and the text of one entry is drawn over the next. The first line says what the window waits for or why the open tab cannot edit, when there is such a state: a pending world choice with its candidate, the gizmo hint, a prepared snap, a confirmed identity, or `EditBlock`. The confirmed identity shows until an edit uses it: Start following, Set binding, a snap's Apply and a coverage Apply pass `consumes` to `Edit`, and a completed one clears the confirmation (`SpatialSelection.Consume`). Below it come `EditFeedback.Messages`: the one result of the last action and, above it, the latest follow-up. `Report` drops everything before it, so no earlier result stays to be read as the current state. A result has the scope of its place. The result of a tab's own action goes when the view it was reported in changes (`EditFeedback.View`, keyed by tab and placement mode). The result of a general place (`EditFeedback.GeneralPlaces`: the footer's Modification, Copy ID and Fit) stays through that change. Every result goes when another object is inspected and when the native map editor's history moves by a native edit, Undo or Redo (`EditFeedback.HistoryMoved`): "Enable completed" is not true after Undo. A refusal reported after the inspection was cleared is kept until an object is inspected again (`Message.Kept`). Give a new place its scope when you add it. Results do not repeat where Undo, Redo and Save are; the first anchor of the outliner says that once. An action that only opens a form, such as Add detection, reports that, for the same reason, and the row is withdrawn when the form closes (`OpenedForm`, `EditFeedback.Withdraw`). A completed preview is a result as well, so it leads an earlier preview refusal. The text stops 4 units short of the area's right edge: the native scroll view lets its viewport run 3 units under its scroll bar. A follow-up is a consequence that arrives by itself after a result, such as terrain output after an activity edit; report it with `Follow`, which replaces the follow-up before it and never a result, and report the result of an action the user selected with `Report`. Every line starts with its source in bold, one space before its text. A result's source is the place it was reported to, so name a place as the modder knows the action group: Placement, Enabled, Track binding. A tab switch changes `inspectorTab`, which is part of the content snapshot, so the footer follows the tab. An object without an editable binding names its own detected reason on the binding's slots and fields (`BindingUnavailable`), before the general reason it cannot be edited. The outliner width is stored in the game's preferences under the window's key, beside the bounds the native window saves there; nothing is written through Unity's `PlayerPrefs`, which is the registry key the user's normal play shares. After a world choice is cancelled nothing counts as confirmed (`SpatialSelection.Confirmed`). The Connections tab serves three structures with the same fields and slots where they apply: the track binding of a generic track marker, the binding of a crossing pad, whose section is titled Crossing pad binding and whose Detach slot is disabled with its reason, and the coverage of a crossing.

Each region has help in the `Help` table: an introduction, short terms and guide links. Each `?` sits in the region it explains, names its scope in its tooltip and keeps its glyph while help is open (`HelpButton`). A `?` opens its region's help in the help window (`HelpWindow`, `NativePresentation.ToggleHelp`): one native builder window, separate from the panel and movable, which shows the region of the `?` that was selected last (`HelpRegion`). It replaces nothing in the panel, so the outliner's anchors and the tab's content stay in view. After its content is laid out, two frames later, `SizeHelp` makes it as high as that content, within 80 percent of the screen, and places it beside the panel, never over it, at the height of the `?` that opened it (`PanelPlacement.Beside`): right of the panel where the screen has room, else left of it. A help taller than the space below its `?` is clamped to the screen and so starts at the screen's top. Its content is 340 wide, which makes the window 364 with its frame. It closes with the `?` of its region, with its own close button, with the panel, and, for the help of a tab, when another tab opens (`CommandBand.ClosesHelp`, `CloseHelp`). A closed native window stays in the UI tree, so the help window is removed on the tick after it closed (`RemoveClosedHelp`) and made again when a `?` asks for it. The title bar holds, left of the close button and from right to left, the window's `?`, the Reset layout icon and the Session details icon (`AddTitleHelp`, `TitleIcon`): native compact buttons without their face (`BareTitleButton`) in the close button's parent, placed from the close button's rectangle, each a bare glyph in the close glyph's colour and named in its tooltip. The game's assets were searched by name for sprites to use: of the icon sprites only `GearIcon` and `LocateIcon` exist, none for a reset or for details, so `ResetGlyph` draws a round arrow and `DetailsGlyph` a page. The page is brighter while the session details are open. The whole-window help starts with the Scene Patcher help heading. When the title bar cannot take the `?`, `TitleHelpProblem` says why and the right band holds a `?` after Copy ID; when it cannot take an icon (`TitleReset`, `TitleDetails`), `TitleIconProblem` says why, the log names it, and the window's help holds a button for it. The first row of a tab body also holds the tab's description. After the native tab strip is built, each tab title gets 8 units of padding and an ellipsis for a strip that is too narrow; the four titles are never renamed. A help term is a field caption above its explanation, and a section heading in a tab is bold body text under a rule (`Section`): the native section header has the small capitals of a field caption, and two of them in a row read as an empty section. Add a term when a feature needs explaining, in the tone of a native tooltip, and put a standing explanation in the panel only where an action needs it.

Status colors are the native Map Editor's: `#FF8080` for a problem or failure, `#E8A33D` for changed, stale or blocked, `#7FB86B` for completed or confirmed, and `#4DCCFF` for a proposed target. Use `Tint` with the constants `Red`, `Amber`, `Green` and `Blue`. World markings use the same meanings through `WorldSelectionOverlay`: gold frames the inspected object, one frame per object; blue marks the chosen candidate; green a confirmed relation; the inspected object has no world label, so its detected problems show in the panel; other choices are neutral. Amber never appears in the world. `ObjectMarkingGeometry.Frame` in the core decides an object's frame, which drawing and picking share, for the gold frame and for candidates alike. The overlay passes every renderer that outlines its object (`ObjectMarkingGeometry.Outlines`): one that shows, and one that the game's distance culling hides now. That is a renderer that a `Helpers.Culling.RendererCuller` or the builder of a curve mesh, such as a crossing pad, holds and has switched off, or a renderer below an object that own culling, a simple culler on it or a game-object culler that lists it switched off, whether that game-object culler stands on the object, on an object above it, such as a crossing root, or in its baked scenery group (`GroupWorld.OffThroughCuller`, `CullingActivity.OffThroughCuller`, `MarkingLink`). A frame and its marker therefore do not change with camera distance or culling. A renderer or object that the scene or a modder switched off does not count. The overlay passes the renderer's world-aligned box and, for a mesh renderer outside a static batch, the corners of its oriented mesh box (`MeshFilter.sharedMesh.bounds`); a hidden renderer reports no world box, so the box around its oriented box stands in. A static batch combines its meshes, so neither the renderer's local bounds nor `MeshFilter.sharedMesh.bounds` are its own there, and a static-batched renderer has its world-aligned box only while it shows. The overlay keeps that box from when the renderer last showed, in its object's own space (`WorldSelectionOverlay.keptBoxes`), and a hidden static-batched renderer outlines with it, carried to the world with its object's current placement, so it follows a patcher move (`ObjectMarkingGeometry.RendererBox`). A hidden renderer with neither a mesh box nor a kept box, a static-batched one that the overlay has not measured while it showed since the world loaded, adds nothing. `ObjectMarkingGeometry.KindOf` leaves out effects (particles, visual-effect graphs such as water spray, lines, trails, billboards and the `VLB.BeamGeometry*` geometry of a volumetric light), shadows-only renderers and renderers of a lower level of detail; the overlay reads each renderer's kind once. The core starts from the part at the object's position, in world coordinates, leaves out parts more than four times its size and 10 metres larger, and joins parts within a quarter of its size, at least a metre, of the growing piece. Only then does it project each part, clipping each face of its box at the six planes of the view volume, so a part that crosses the near plane or a view edge still outlines a near object, and a part outside the view adds nothing; only the overlap with the oriented box counts. An object far to the side with little depth would otherwise project its corners over more than the whole view. The frame is the convex outline of the included parts on screen (`ObjectMarkingFrame.Outline`): of each part its oriented box, or its world-aligned box where the oriented one is unknown, each face clipped to the view, with the margin around the points. A rectangle around a box that stands at an angle to the view is larger than the box at its corners, which made frames overlap; the outline is not. It stays convex, one closed line per object, so a point is tested against it with one pass over its edges, and drawing (`OutlineStroke`) and picking (`Contains`) share it. `Frame` is the rectangle around the outline. The marker stands on `ObjectMarkingFrame.Marker`, the center of the one box the outline is drawn from: a point of the object, so the marker stays on it as the camera zooms and turns, where the center of the rectangle on screen would wander. Where that point is not in front of the camera or falls outside the rectangle, the marker stands on the rectangle's center. Beyond the frame distance the marker stands on the center of the box uncut by the ground, so no ground is read for an object that shows only its marker. The inspected object is projected without a frame distance, so its frame and marker stay at any camera distance and while culling hides it. A crossing pad lies on its track: the ballast and the road it crosses are no ground it stands in, so it is framed whole. The frame is the object's outline projected onto the screen: tight, in straight lines, turning with the object, because it is built from each part's own oriented box. All parts of one object, and of a grouped object, share one box: the outline around the union of the cut parts. Every part is cut off where it meets the surface it stands in, terrain or ballast, whatever its width, so the frame shows only what stands above it. That surface is `ObjectMarkingGeometry.Surface`: the terrain, or the ballast of track that lies at most `BallastDepth`, 1 metre, above that terrain. Track that is carried higher over the terrain, as on a bridge deck, is no surface an object stands in, so a bridge is cut only where it meets the terrain at its ends. The overlay reads the heights with one ray from above against the game's Terrain and Track layers, the track collider standing for the ballast, once per half metre of the world (`WorldSelectionOverlay.GroundAt`), and reads them again after an origin move, a move of the native map editor's history, a completed terrain output and a track that moved (`ClearSurface`). A build without one of the layers is cut at the terrain alone, or not at all, and says so once in the log. A part is divided along each of its own axes, read from its corners, into pieces of `GroundPiece`, 10 metres over the ground, and into at most `GroundPieces`, 5; along an axis longer than 50 metres the five pieces are a fifth of that axis each. Each piece is cut at the surface under its center, so a long platform on a slope is cut along the slope. Burial is decided for the object: an object all of whose parts lie under the surface found from above, as in a tunnel or under an overhang, is framed whole, because that surface is not the ground it stands in; otherwise every part and piece that lies wholly under the surface is buried and adds nothing. A piece that lies inside the view is projected by its corners above the surface and the points where its edges cross it; only a piece that crosses a plane of the view volume has its faces clipped there. The frame distance is 500 metres: beyond it an object shows only its square marker. A static-batched part, as baked scenery such as a station building is, has only its world-aligned box: around a building that stands at an angle that box is wider than the building, and so is its frame. The game data allows no tighter one. Close up the frame always shows, also when it fills the view. Beyond `ObjectMarkingGeometry.FrameDistance`, measured from the camera to the bounds of the framed piece, the object shows only its colored marker and label. Its value is 500 metres: measured in the game in 50 metre steps from 100 to 600 metres, every frame still surrounded only its own object at 550 metres with the pointer over each, less one step; the 600 metre step was not checked by hover. It equals `MapEditorGizmoRenderer.MaxGizmoDistance`, 500 metres by default, up to which the native map editor draws and picks its own object markers; it draws segments up to 1.25 times that.

The outliner (`DrawOutliner`) holds a top row with the native filter field, its `?` and the Fit button beside the divider, then the All, Changed, Disabled and Problems segments, All first and the rest by name. A native segment is as wide as its word plus 12 units of padding and the segments have no spacing, so the four need 292.4 units (`CommandBand.FilterSegments`: All, Changed and Problems measured in the game, Disabled from the glyph advances fitted to 168 measured labels); the column's default and least width of 296 (`CommandBand.OutlinerWidth`) holds them. A new or renamed filter changes that sum: recompute it and the widths that follow from it, a count line, the `AddOutlineView` rows under one folder per family, after those the Inspection only group while it holds entries (`InventoryPresentationState.Groups`, `InspectionOnlyGroup`), and three anchors. A row of that group shows its family behind its name, has no problem marker and no edit; the Object tab starts with its reason. The Object tab lists `SceneObservation.Notes` under Inspection notes, in plain text without the problem marker. Its Track group line names Disable and Clear activity only for an object that offers them (`CommandBand.TrackGroup`). A row's markers stand directly before its name and take room only on a row that has them, so the column's width goes to the names and the end of a long name can be cut off without losing a marker. A folder row starts with its count, followed directly by the family name. A name that repeats in its folder carries its parent, dimmed; an inactive object's name is italic. `InventoryPresentationState.Rows`, `Groups` and `FitWidth` decide which entries show, how they group and how wide the column becomes; `PatchEditingSession.IsChanged` reads the scene patch file alone, so it can be asked for every row.

Use `PatcherBehaviour.Button` for a compact action that requests a content refresh after its callback. Use `Heading` for a heading in the native H3 style. The inspector reserves 24 units for its object name and the line below it. The full object path appears in the name tooltip. The Inspector and Guided switch sits to the right of the family and badges. A line with an ellipsis draws nothing when its rectangle is lower than its text line by any fraction, so do not give such a line a height below what the text needs. Use `PlainLabel` for scene and scene patch file text, `Field` for a named value, `FieldLabel` above an input field and `Section` for a group heading, which draws a rule above the native section header so that a heading differs from a field label. `ValueField` builds an input field, or the value as text of the same height without the input frame when the object cannot be edited now. `BindingFields` shows an observed line of the form `Marker id=...; type=...` as named values. `Breakable` lets a path wrap after a separator. `Field` shows the native field label above a left-aligned value; every tab uses this one form, so the same kind of element has the same size, weight and colour everywhere. A state that appears in more than one place has one markup constant, as `ChangedBadge` has for the state line and the Changes tab. Text from the scene passes through `Literal`, so it cannot act as markup.

The native window saves its bounds when the user moves or resizes it and when it is shown or closed. It is shown before the layout places it at its default position, so the presentation raises the window's own moved event after that placement (`SaveBounds`); the next native map editor session then restores the placed bounds instead of the window's initial top-left position. The presentation uses `WindowManager.CreateWindowWithComponent<ScenePatchWindow>`, the manager's window prefab and builder assets, and `BuilderWindowBase` panel ownership. Fields, headings, tabs, segments, scrolling and buttons use native builders. The constructor refuses to build when a builder asset the layout uses is missing. Native Save, Undo and Redo keep their existing owners. Existing prompts use the checked native modal factory in `Hooks`; new prompts must preserve their feature's cancellation, outstanding-work and session guards.

`PatcherBehaviour.Edit` queues the edit through `Queue`, which also serves every other request that needs an inspection token: the guided Target pin, the Review comparison, guided Apply, the crossing coverage preview, preparing a snap after its target is confirmed, and starting the gizmo. No panel action except Refresh, and the first fill of an empty inventory, compares or discovers the whole scene in one frame. When the snapshot was compared since the last foreign change of the native map editor's history (`Compared`: a refresh or a completed pass under the current history value, at most two minutes ago), the request runs in the next frame. Otherwise the first message slot shows the action group with "Working..." while a stepped pass compares the whole scene, 8 milliseconds a frame. The waiting request lives in `RequestQueue`, which the core tests compile. It belongs to the open panel and its native map editor: closing the panel, leaving the native map editor (`Detach`), clearing the inspection (`RequestQueue.Release`, which drops the object's results first so the refusal stays) and ending the load attempt cancel it with a refusal that names the reason, so it never runs later and no pass steps for it while the window is closed. The patcher's own edits, Undo and Redo keep the snapshot compared (`OwnChange`), because their objects are observed again; no pass steps between such a change and that observation. No pass steps while a gizmo is active either: the placement of its target is the patcher's own preview, and its target is observed again when the gizmo ends, by a release or a cancellation. Escape cancels a pending world choice or an active gizmo through a transient handler of `UI.GameInput` and is consumed, so the pause menu stays closed. Escape never calls `ClearInspection`. An open choice list closes first, then Escape cancels a drag, then a pending world choice. Over the panel it can also cancel a standing or queued gizmo or a prepared or queued snap (`EscapeGizmo`, `EscapeSnap`); otherwise it is left to the pause menu. Clear and a click on the inspected row (`CommandBand.ClearsInspection`) remain the routes that end inspection. With the pointer over the world, Escape cancels only the pending choice or an active gizmo. Clearing the inspection goes through `RequestQueue.ReleaseInspection`: a pending world choice is cancelled first, by the same `CancelSelection` as the footer's Cancel, so the native map editor takes the world's clicks again; then gizmo, snap and form are restored; last a waiting request is refused. Escape elsewhere still opens the pause menu. The idle comparison that informs the band takes a 2 millisecond step on every third frame, pauses five seconds after a pass, and starts at once at the edit's pace when the native map editor's history changes by something other than this patcher. One unit of a discovery, such as the search for all components, can still exceed a step's budget. When the pass ends the edit runs: refused when the pass found a difference or the native map editor's history changed meanwhile, otherwise applied behind its guard. A completed edit reports its result and calls `RefreshAfterEdit`, which observes the edited object and what belongs with it again two frames later. A change of the inspected object's terrain output is reported as a follow-up from `TerrainSnapshot`. Until that observation the inventory holds the object as it was before the edit, so an edit in between is refused as changed. Resolving a target walks down from the roots of its scene along the path (`BoardScene.LoadedAt`), so its cost follows the path and not the size of the scene. A closed window does no per-frame presentation work: the content snapshot that requests refreshes is computed only while the window is open. Keep work that searches the scene out of that snapshot. A value the panel reads every frame for the inspected object resolves its target once per observation, as `InspectedOutput` does for terrain output; every inspection, refresh and completed edit produces a new observation. The outstanding-work text is recomputed when the native map editor's change counts, the last Save or an incomplete operation change, and once a second.

## Guided tasks

`GuidedTaskState` holds the pinned target and draft values for the active task. Back from Review returns to Values and keeps the draft; Back from Values returns to Target and clears the pin and draft. Cancel ends the task and clears its target and draft. Complete records the result and moves to Applied after success. While Values or Review is active, Clear and clicking the pinned object's row cancel a pending world choice and clear its prepared snap, keeping the target and draft. Escape cancels pending interactions without ending the inspection or the guided task. Without a pending choice, Clear and a click on the pinned row are refused with the feedback used when selecting another object. Return to Inspector cancels the guided task explicitly.

`DrawGuided` reuses the native field, section, segment, scroll and action-row builders. Its Target, Values, Review and Apply step titles are inert native Toggle components, which retain the native selected and unselected appearance. The footer row uses `GuidedActs` while Guided mode is active and no world choice is pending. Guided mode retains the previous inspector tab and restores it when leaving Guided mode, including cancellation and Back to inspector. Apply and returning to Target leave Guided mode open. Feedback uses one view key per guided step. Entering Values, Review or Target clears results from the preceding step. Entering Applied preserves the new Apply result; restoring the inspector tab also preserves it, while a later ordinary tab change clears a tab-local result as before. Explicit Refresh clears earlier messages without releasing the inspected object or changing the feedback context. Queued Review and Apply requests show no recovery text; their refusal callbacks set it. `EnteredEditValues` parses placement and track-location fields for both modes. Its FillTrackLocation helper fills segment, end and distance together after validation. The shared confirmed-click path supplies the inspector fields and the guided Picked action with that complete track location. Guided Apply uses `Edit` with the same action text and world-choice consumption flag as Inspector; its completion callback updates the task state after the shared feedback and refresh path.
