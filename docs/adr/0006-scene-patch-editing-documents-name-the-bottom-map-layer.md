# Scene patch files from scene patch editing name the bottom map layer

A scene patch file that scene patch editing creates names as its target map the bottom map layer of the edited map definition, the lowest of all layers the game composes for it, layers of layers included. It names the edited map definition itself when that has no map layers. A scene patch file still applies when its target map, or a map that inherits it as a map layer, is loaded, and the patcher neither detects map-changing scripts nor remaps a target map at runtime. Players of a map-changing mod play the base-game map, where the edited map definition is not loaded, so a scene patch file naming that definition never reached them; with the bottom layer as target it applies on that map and on every map layered on it, the mod's own included, which is the reach the game gives the mod's map-changing script. Detecting where a mod's native changes landed was rejected because mods that change only speed limits, industries or scenery leave nothing to detect, and resolving the layer at runtime was rejected because the stored id would no longer say where the scene patch file applies. Native changes reach a save on the base-game map only through such a script, so every mod meant for that map carries one; a mod without one is played on its own map, where its scene patch files still apply, while on the base-game map only its scene patches would appear. Once mods ship scene patch files with this target, a different rule changes where distributed scene patch files apply. An existing scene patch file keeps the target map it names; a modder who wants a scene patch file on the mod's own map only sets that id by hand. See [the target-map finding](https://github.com/CrankyAnt/RailroaderScenePatcher/issues/38#issuecomment-6911178789).
