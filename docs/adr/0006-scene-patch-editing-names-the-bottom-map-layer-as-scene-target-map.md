# Scene patch editing names the bottom map layer as scene target map

A scene patch file that scene patch editing creates names as its scene target map the bottom map layer of the edited map definition, the lowest of all layers the game composes for it, layers of layers included. It names the edited map definition itself when that has no map layers. A scene patch file still applies when its scene target map, or a map that inherits it as a map layer, is loaded, and the patcher detects neither map-changing scripts nor map patches, and it does not remap a scene target map at runtime. Players of a map-changing mod usually play the base-game map, where the edited map definition is not in the map context, so a scene patch file naming that definition never reached them; with the bottom layer as its scene target map it applies on that map and on every map layered on it, the mod's own included, which is the reach the game gives a map patch. Detecting where a mod's native changes landed was rejected because mods that change only speed limits, industries or scenery leave nothing to detect, and resolving the layer at runtime was rejected because the stored id would no longer say where the scene patch file applies. Native changes reach a save on the base-game map only through a map-changing script or a map patch; a mod with neither is played on its own map, where its scene patch files still apply, while on the base-game map only its scene patches would appear. Once mods ship scene patch files with this target, a different rule changes where distributed scene patch files apply. An existing scene patch file keeps the scene target map it names; a modder who wants a scene patch file on the mod's own map only sets that id by hand. See [the scene target map finding](https://github.com/CrankyAnt/RailroaderScenePatcher/issues/38#issuecomment-6911178789).
