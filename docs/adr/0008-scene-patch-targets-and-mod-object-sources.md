# Scene patch targets resolve exactly and a mod object's source falls back to a conforming instance

A scene patch file names a target by scene, hierarchy path and component, and a target resolves to exactly one object. Where a hierarchy path and component are not unique, the target adds a key: the game's own key where one exists, such as a marker ID, else the object's position in the map, matched exactly within a small tolerance. A mod object has an identity that the mod assigns, as an added crossing light, gate or bell has its Equipment ID. Nearest-object substitution is forbidden for targets and for equipment sources, because a modification must never land silently on another object than the one it names. A mod object's source is the one exception: it is preferably the original, and when the original is missing, the first loaded instance with the same model and build, in a fixed order, with a warning in the log, never chosen by distance. Without that exception, every mod object would break when a game update removed its original, and each modder would have to make it again; with it, a mod object keeps working as long as the game holds one identical instance. Many identical scene objects share a hierarchy path on purpose, such as a location sign at each end of a place, and the game never looks them up by path, so telling them apart hides no problem in the game. Real problems such as duplicate marker IDs are still detected. The cost is that a game update that moves a keyed object refuses its modification with the reason, as for any missing target. See [finding #156](https://github.com/CrankyAnt/RailroaderScenePatcher/issues/156) and [finding #157](https://github.com/CrankyAnt/RailroaderScenePatcher/issues/157).
