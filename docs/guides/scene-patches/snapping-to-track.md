# Snap an object's position to a track

Snap a supported object's position to a track in the native map editor. The object needs a supported fixed-placement adapter. Open **Scene Patcher**, click **Refresh** in the command band, inspect the object, and click **Snap** on the **Placement** tab. Check its current physical placement and logical relationships before starting.

1. Click **Track** at the bottom of the tab to pick a track segment, or **Node** to pick a track node. Click the track ribbon or node marking in the world. Navigate with the camera as needed.
2. Check the candidate's ID. A segment also shows both endpoint IDs; a node shows its map position. If candidates overlap, choose one explicitly in the session details (the page icon in the title bar). Until you confirm, **Target** on the **Placement** tab shows it as a candidate, and a **Next** line names the step that follows. Use **Focus** in the footer to inspect it.
3. Click **Confirm** in the footer. The **Placement** tab shows the snap target under **Target** and the resulting map position under **Position**. Confirmation prepares the operation without moving the object or adding history.
4. Click **Apply** at the bottom of the tab. For a segment, the patcher moves the object to the closest point on that segment's cubic curve, including its ends. For an endpoint, it uses the node's exact position. Both keep the object's rotation, activity, and logical binding. Neither adds a lateral or height offset.
5. Use the native **Undo** and **Redo** controls to reverse or reapply the completed edit. Use the native **Save** button to persist it, then reload the world when you need to verify fresh-world reconstruction. Reload ends the native map editor's Undo/Redo history.

Click **Cancel** in the footer before confirmation or **Discard** at the bottom of the tab afterwards. Switching to another placement mode drops the snap target and any prepared snap. Closing the patcher panel, refreshing, or changing the inspected object also clears a prepared snap.

Starting **Move** or **Rotate** in **Gizmo** mode discards a prepared snap. Starting a world selection cancels an active gizmo and restores its captured state first. While the gizmo owns input, complete or cancel it before using the snap or numeric placement controls. Snap and completed gizmo gestures use the same native Undo/Redo and Save routes. See [move and rotate with a transform gizmo](using-transform-gizmos.md).

Before moving the object, the patcher rechecks the object, loaded map context, selected graph identity, native handle, and copied geometry. If the target is missing, ambiguous, replaced, or changed, the patcher refuses the operation. It never substitutes a nearby track. Correct the cause, then inspect and select again. If the move fails, the object's placement adapter restores its previous state. If restoration can't be verified, further edits stay blocked until an explicit recheck succeeds or the world reloads.

Save writes the resulting placement as [`placement.mode = "fixed"`](scene-patch-file-v1.md). The saved scene patch file does not retain a snap target or resolve that track on reload. Later changes to the track do not move the snapped object. To keep an object at its position relative to a track as that track moves, use [track following](following-track.md) instead. Changing a physical position does not repair or replace a logical binding. On a track marker, a snap moves the object and leaves its stored track location and its named location unchanged; change that binding as described in [repair, replace, or detach a track-marker binding](repairing-track-bindings.md).

The controlled tests cover selection refusal, fixed scene patch file persistence, origin conversion, repeat application, and restoration. Native geometry, visual presentation, native history, and fresh-world reconstruction require a Railroader journey on the tested build and fixture; a successful assembly build alone does not verify them. Board placement can also regenerate terrain output; see [move a board with its terrain effects](moving-boards.md). Bridge placement has its own collision and separate-scenery checks; see [move or disable a bridge with its collision](placing-bridges.md).
