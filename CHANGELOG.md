# Changelog

This changelog lists notable changes, newest first.

## 0.5.0

- After **Reload Map Editor**, the **Scene Patcher** icon is back in the top-right strip. During **Select in world**, a click in the world no longer opens the game's own windows, such as a station agent's. A part of a baked scenery group reads **Part** in the world choice and on its state line. With **Debug logging** on, the Player log records each confirmed world choice. **Session details** show the supplied definitions as saved, and the **Inventory** line says that it describes the last full read.
- The **Scene Patcher** window has a compact mode: click **Compact window**, four corners pointing inwards in the title bar, to switch to a narrow side rail at the right edge of the screen that leaves more of the world in view. The rail follows the open tab or guided task and keeps the inspected object, a pending world choice, and a placement in progress. It shows the command band, the object's name and state, a few lines about the object, a six-line message area with the tab's actions or the world choice's **Confirm**, **Cancel**, **Focus**, and **Details**, and an outliner of six whole rows that **Hide outliner** hides. Tabs, the search field, and the outliner filters stay in the full window; click **Full window** to return. You can drag and resize the rail; it keeps its place for the session, and the full window keeps its own saved place. **Reset layout** now also puts the help and the session details back beside the window, and in the compact window it returns to the full window. The window and help titles now read **Scene Patcher** and **Scene Patcher help**. See [use the compact window](docs/guides/scene-patches/inspect-scene-objects.md#use-the-compact-window).
- A help window that is too long for the screen, such as the outliner's, opens wider so that it fits. It can now use the whole height of the screen. If it still doesn't fit, scroll it to read the rest. The mouse wheel scrolls a help window as fast as the outliner, also at a larger UI scale, and reaches the end of a long help such as the outliner's. A help window never covers the Map Editor window's title bar and close button, and an open help takes the size and place that fit a new UI scale.
- The outliner shows the inventory as one tree with two views. **By category** lists category, then kind, then place, then the objects. **By place** lists place, then category, then kind, then the objects. Every list is in alphabetical order, and numbers compare by value, so `T-2` comes before `T-10`. A row's tooltip appears after about half a second.
- An unprotected crossing without a crossing controller is a game-defined group: its crossbucks and pads. You can select it in the outliner or in the world. Beyond 125 metres it shows as one square marker and one object frame, as a grade-crossing setup does.
- A hierarchy path that several objects share is refused with the reason "N objects have this hierarchy path, and a scene patch file names an object by its path". The footer says that the object can't be edited while another object has the same hierarchy path.
- The **Editing ready for** line names the scene patch file's path from the game folder, or from the mod's own folder for a mod outside the game folder, such as `SelfMadeMapTest/Data/scene-patches.json`. It no longer shows the full path.
- A scene patch file for a map other than the loaded map or one of its layers now produces a warning in the game's **Log**. The warning names the supplying mod and its `Data/scene-patches.json` and explains why the file was skipped. The game's editor default map, which loads when you click **Editor** in the main menu, adds no such warning. Previously, only the Player log recorded the skip. The other scene patch files still apply. Observed in Railroader 0.6.3: the warning names the file's mod and map, the other files still apply, and loading the editor default map adds no warning.
- Disabling an existing crossing mast or bell that a progression controller or map feature switches is now refused if the disable couldn't hold. As with station groups, the patcher gives the reason before changing anything. Previously, a scene patch file could apply a disable that might not hold. No base-game crossing has such a mast or bell in Railroader 0.6.3.
- The guided task list of a starter placement marker offers **Start derailed**, which sets whether the car cut starts as a wreck through **Target**, **Values**, **Review**, and **Apply**. It uses the same operation as the **Start derailed** checkbox on the **Connections** tab and is unavailable for the same reasons.
- **Recheck** is now `refused` when the patcher refuses the object's modification, such as a crossing addition whose source doesn't conform to its pattern. It gives the reason and changes nothing. Previously, it reported `failed; cleanup is incomplete` and guarded the crossing. Other additions of that crossing stopped by the refused addition now appear as **Not built**, naming the refused addition instead of offering **Recheck**. A valid addition whose modification is refused for its detection or a dependency gives that reason. You can correct or remove a refused addition on the **Connections** tab while another refused addition remains. Open its **Edit** form and click **Use** to change its source while keeping its equipment ID and placement. The footer repeats the preview, such as `Nothing is built, because the modification stays refused`. While another refused addition keeps the crossing refused, the correction changes only the scene patch file. Once no refused addition remains, the additions are built. Undoing the change that built them returns the crossing to the refused state. Recheck checks only modifications that take effect. An entry that shares an addition ID, misses a dependency, or isn't executed therefore no longer causes Recheck to be refused. On an added light, gate, or bell, the footer and the `Unavailable:` tooltips now direct you to its crossing controller's **Connections** tab instead of saying `This object cannot be edited here.`
- You can give a track marker a replacement ID, so that one of the scene markers that share a marker ID can change its activity, track binding, or track following without removing the registrations of the others. In the **Connections** tab of the marker, enter the ID in **Replacement ID** and click **Set ID**; **Clear ID** returns the underlying ID. The base-game markers `Mg6m` (the active speed sign and the inactive yard limit) and `Mkft` (the `Whistle Sign W` markers) are the cases. Only an object in the **Track marker** family takes an ID. An ID that another scene marker or a map object uses, that begins with `passengerStop:` or `flare:`, or that begins or ends with a space, is refused, and every ID is refused while the game has not loaded the map objects. Scene patch editing writes `dependsOn` for a holder whose activity, binding, or track following needs the replacement IDs of the other holders. Observed in Railroader 0.6.3: a repaired marker registers under its replacement ID while the other holders keep their registrations, also after Save and a world reload. Scene patch files with a replacement ID require patcher 0.5.0. See [repair a duplicate marker ID](docs/guides/scene-patches/repairing-duplicate-marker-ids.md).
- A disable now holds when the game's progression or a map feature switches the object on: the station groups `Cochran flagstopstation`, `Alarka Depot`, and `Alarka Jct Station`, the track marker on `Hemingway flagstopstation`, the 13 station map icons that progression switches, and the track markers `Sign Begin CTC Andrews` and `Sign Begin CTC Sylva`, which the `signals` map feature switches. Without a disable, the game switches these objects as before. For a disabled object that the game switches, the **Object** tab and the footer's message area show an amber warning; **Enable**, **Clear activity**, Undo, or **Remove modification** returns the object to the state that the game's switch gives it now. While the game keeps an object off that you did not disable, **Enabled** reads `Yes, but currently switched off by the game`. A disable that could not hold, because the patcher cannot share the object's activity in this load or the game's progression or map feature members are unavailable, is refused with the reason before anything changes. Observed in Railroader 0.6.3: a disabled `Cochran flagstopstation` and its station map icon stay off after progression switches them on, also after Save and a world reload, and a disabled `Sign Begin CTC Sylva` stays off with the `signals` map features on. The other objects, **Yes, but currently switched off by the game**, and the refusal are not yet observed in Railroader.
- You can move, rotate, or disable the road bridges so that each stands where you moved its road in the native map editor: the 14 road bridges below `World/Large Scenery` and the `World/Roads` folders, including the 60-metre bridge at US19 Gov Island beside its grade crossing. They are groups under **Bridge** > **Road bridges** in the **Baked scenery group** family, with their parts, and are no longer `inspection only`. A bridge moves with its colliders, its culling, and the ground mask on its root: the patcher asks the game to rebuild the mask at the bridge and tracks the terrain output at the old and the new place on the **Changes** tab. The road stays native map data, and a road bridge takes no track-following placement: **Follow** is unavailable for it. `Old Home Town Road Bridge` cannot be moved, because its mask flattens the terrain height; it can be disabled. The smoke decals beside two Dillsboro bridges are separate scene objects, which the patcher does not move. Observed in Railroader 0.6.3: a moved road bridge shows at its new place with the terrain and trees updated at both places, Undo, Redo, removal, and a world reload restore it, and a disabled bridge is gone. Rotation and collision at the new place are not yet observed in Railroader. Scene patch files with these targets require patcher 0.5.0. See [road bridges](docs/guides/scene-patches/moving-baked-scenery-groups.md#road-bridges).
- You can inspect and disable the flag-stop stations `Alarka Jct Station`, `Cochran flagstopstation`, `Ela flagstopstation`, `Nantahala Station`, `Rhodo Station`, `Topton Station`, and `Wilmot Station` and the depots `Alarka Depot`, `Almond Depot`, `Sylva Depot`, and `Southern Combination Depot` with their parts. They are now groups under **Station building** in the **Baked scenery group** family and are no longer `inspection only`. The scene ground mask of each is its part `Mask`: a move of the group or of `Mask` rebuilds the mask at its new place, which asks the game to regenerate the terrain and vegetation there, with the terrain output tracked as for a board. Their masks flatten the terrain height, so the patcher refuses to move the groups and their `Mask` parts until a Railroader test confirms that the game restores the height after **Undo** and removal. Their other parts can be moved, and every object can be enabled or disabled. `Hemingway flagstopstation` stays in the **Track marker** family, and a placement of it is refused for the same reason; an existing scene patch file that moves it fails that modification on load. The game's progression switches some of these stations on and off; a disable holds against it. Observed in Railroader 0.6.3: the 11 stations are listed with their `Mask` parts, a disable and **Enable** regenerate the terrain, another part moves, and the moves of a group, a `Mask` part, and `Hemingway flagstopstation` are refused. A move that rebuilds a mask is not yet observed in Railroader. Scene patch files with these targets require patcher 0.5.0.
- You can repair the construction segments of a rail bridge after you split or replaced its track in the native map editor: on the **Connections** tab of `Bridge 1` at Bryson, the `Almond Bridge`, or `Ela Bridge Scenery`, pick the new segments with **Segment** and **Picked**, or type their IDs, and click **Set**. The construction's segments are then exactly those segments; **Clear segments** returns the native segments. A missing or ambiguous segment is refused with its ID, and the segments cannot be detached. **Picked** removes a segment that no longer exists from the field. In the guided task list of `Ela Bridge Scenery`, the track binding, starter placement, and replacement ID tasks stay unavailable with the controller's own reason. A construction segment that no longer exists is a problem of the construction, marked **!** in the outliner and named under **Detected problems**, where **Repair construction segments** opens the **Connections** tab. `Ela Bridge Scenery` is no longer `inspection only`: its construction segments are its only edit, and its placement and **Enabled** stay unavailable. Scene patch files write the relationship as `relationships.constructionSegments`, and the Ela controller as `bridge-construction-scenery-v1`. Observed in Railroader 0.6.3: the repair of `Bridge 1` after a split, with Undo, Redo, removal, and a world reload, the problem mark, and the refusals; the `Almond Bridge` repair and **Picked** removing a segment that no longer exists are not yet observed in Railroader. When a construction names a segment that no longer exists and a scene patch file repairs it, the construction's update at world load waits until the patcher has applied the file. Observed in Railroader 0.6.3: the game reports no restore error for the repaired construction. Scene patch files with construction segments require patcher 0.5.0.
- You can move, rotate, or disable player spawn points, such as `World/POIs/Alarka`, so that players start, teleport, and are rescued at places that fit your map. The scene spawn points are listed in their own **Spawn point** family and show a helper marker in the world. On the **Object** tab, **Use in the game** names each expected use: the rescue of a stuck player to the closest active spawn point, the `/tp` console command by name, and each active start setup that names the spawn point, with its condition. The default start of a new game appears only on the spawn point where a new game is expected to start, when the map declares no native spawns; if several active spawn points share the highest priority, each says that a new game starts at one of them. When the map declares native spawns, the tab names such a setup without saying that the game starts at the spawn point. For a disabled spawn point, the tab says that rescue and teleport pass it by. An inactive spawn point is not a problem. Native spawns in `Map.json` stay with the native map editor's **Spawns** category. A baked scenery group that holds a spawn point is not moved as a whole. Observed in Railroader 0.6.3: a new company game starts at a moved spawn point, and `/tp` puts the player at its moved place and rotation. Rescue, and a disabled spawn point passed by in the game, are not yet observed in Railroader. Scene patch files with these targets require patcher 0.5.0.
- You can move, rotate, or disable a station map icon so that the map shows the station where it now stands. The icons below `World/Map Labels/Station Icons` are now listed in their own **Station map icon** family, each once, and the `Station Icons` folder is no longer marked inspection only. Move the station's track span, depot house, and station agent in the native map editor first, then the icon with the patcher; the patcher does not couple them. The game's progression switches an icon on or off with its station; a disable holds against it. Observed in Railroader 0.6.3: the map shows a moved icon at its new place, also after a world reload, and a disabled icon stays off. Rotation is not yet observed in Railroader. Scene patch files with these targets require patcher 0.5.0.
- You can move, rotate, or disable the rail bridges outside Ela so that each stands where you moved its track in the native map editor: `Bridge 1` at Bryson with its abutments and steel, the `Almond Bridge` with its abutments and steel, and each of the seven plate girder bridges. They are groups under **Bridge** > **Rail bridges** in the **Baked scenery group** family and are no longer `inspection only`. Abutments and steel of the Almond Bridge are now parts of one `Almond Bridge` group. Colliders and culling move with the bridge, and the patcher checks that each collider keeps its shape and enabled state and that the nearby generated trestles stay unchanged. The track stays native map data with its own trestle or steel flags; **Follow** is unavailable for rail bridges. The **Object** tab names the construction segments whose construction state switches parts of Bryson Bridge 1 and the Almond Bridge, and the **Connections** tab lists each one and marks a segment that no longer exists. A disable holds against the construction controller, with an amber warning on the **Object** tab and in the footer; **Enable** returns the object to the controller. Observed in Railroader 0.6.3: a moved construction shows its construction state and culling at its new place, a train runs over a bridge moved with its track, and a disabled part stays off when its segment is complete. Rotation and collision at the new place are not yet observed in Railroader. Scene patch files with these targets require patcher 0.5.0.
- You can move or disable `Bryson Section House`, the tower `Bryson Tower Chance Clayton`, `Bryson Turntable`, and `Roundhouse 3` with their parts. These buildings now stand under **Railroad service building** in the **Baked scenery group** family and are no longer `inspection only`. The game keeps the state of a lantern or roundhouse stall by its key, not by its position, and reads no position for it. On the **Object** tab, **Use in the game** names each lantern switch and door toggle with its key, the object that holds the saved states with their ID, and the tower's name text. Disabling that object, or a group or part above it, warns that a game save might not keep the states. A lantern's flame, which the game turns toward the camera, has no row. The object that animates a stall's doors has no row; move its stall instead. A group that holds a pickable toggle is no longer left out of the family. Observed in Railroader 0.6.3: a moved Section House lantern stays lit, the doors of a moved turntable and stall open, and both states hold after Save and a world reload. Moving or disabling the tower and `Roundhouse 3` is not yet observed in Railroader. Scene patch files with these targets require patcher 0.5.0.
- You can move, rotate, or disable the lake surfaces `Fontana Lake (1)` and `Fontana Lake (2)` and the `Whittier Log Pond` group to fit a changed river or track. They are now groups in the **Baked scenery group** family: `Whittier Log Pond` under **Storage display**, with its lake surface and its log pond as parts, and the Fontana lakes under **Water**. The patcher moves the water mesh with its object and refreshes the culling of the lake and the log pond; the native lake masks and rivers stay with the native map editor. A move of a lake surface that the game draws from a static batch is refused before anything changes. On the **Object** tab of `Whittier Log Pond` and its log pond, **Use in the game** names the sawmill storage that the log pond shows and says that moving or disabling it does not change that storage. In the world, the log pond is framed by the area it lays its logs out in. Observed in Railroader 0.6.3: none of the base map's lake surfaces is statically batched, the water follows a moved group or lake, and the moved log pond's logs follow the sawmill's storage. Scene patch files with these targets require patcher 0.5.0.
- The `Coal Loader` group at Robinson Gap Mine is a decorative group under **Industry building**, like the other Robinson Gap Mine groups, and you can move or disable it with its parts. The game loads Robinson Gap coal by teleport between the industry's native track spans, not at the loader, so moving or disabling the loader doesn't change where loading happens. An object with a `KeyValueBoolAnimator` is no longer listed as a part of a baked scenery group; it moves with the object above it.
- You can move, rotate, or disable the storage piles of `Andrews Snowbird Paper`, `Sylva Paperboard`, and `Connelly`, one pile at a time or as a whole storage display, to make room for extra track. These displays are now groups under **Storage display** in the **Baked scenery group** family, with each pile as a part, such as `Connelly / Log Pile L1a`, and the piles are no longer marked inspection only. On a pile's **Object** tab, **Use in the game** names the storage that the pile shows and says that moving or disabling the pile does not change it. A moved pile keeps showing its industry's storage, and its logs, collider, and culling move with it. In the world, each storage display appears as one group with all its piles, and a pile has an object frame around the box of its logs. For a decorative industry building under **Industry building**, such as `Bryson Coal Dealer`, the tab says that the industry works on its native track spans. Industry positions, track spans, and their delivery and loading points stay with the native map editor. Scene patch files with these targets require patcher 0.5.0.
- When `Data/scene-patches.json` changes outside the native map editor, a **Version choice** panel replaces the inspector tabs until you click **Use file version**, **Keep editor version**, or **Import**. A file that needs repair shows a **Repair** panel with its diagnosis instead. While either panel is open, every other Scene Patcher control except **Refresh** and the session details is unavailable. Tooltips explain why, and the message area shows results only.
- **Import** brings outside changes into a running session. It lists each new, changed, or removed entry and each conflict with your own edits. After you choose the editor or file version for each conflict, it applies everything at once. Nothing is written until Save. Import adds no Undo step, keeps your other edits, and restores the session if a change fails. Save is refused while the Import panel is open.
- The outliner shows baked scenery groups under their categories: Station building, Platform, Lights, Sign, Grade crossing, Bridge with the kinds Rail bridges and Road bridges, Industry building, Storage display, Railroad service building, Water, Road scenery, and Unclassified. Each group's parts are rows beneath it. A group without a supported edit stays under its category, marked `inspection only`. Road bridges below the `World/Roads` folders appear under Road bridges, and `Ela Bridge` and `Ela Bridge Scenery` under Rail bridges. A search that matches only a part shows its group's row dimmed.
- Bryson Yard is a folder, not a group: each of its 13 yard lamp posts is its own group under Lights. A scene patch file modification that targets Bryson Yard as a group, or one of its lamp posts as a part, fails with that reason, and the file's other modifications still apply. `Almond/Cube` and `Bryson/Bryson Appalachian Hardwoods` are no longer listed.
- A group's square marker contains a small hollow square instead of `+`. Beyond 125 m, only the group appears. At 125 m or less, a baked scenery group with parts shows only its parts. On a part's **Object** tab, click **Select group** after the `Part of:` line to inspect the group.
- A station building group contains the inventory objects below its root, a rail bridge construction contains its construction controller and the objects whose visibility the controller sets, and an industry storage display contains the storage piles that one industry's storage fills. Each appears as one group beyond 125 m, as `Ela Bridge` and `Ela Bridge Scenery` do.
- Culling containers, such as `Bryson House Track / Culled`, are no longer listed as parts of a baked scenery group and appear in no world choice list. The parts in them stay listed under their group. A scene patch file modification whose path names a culling container fails with that reason, and the file's other modifications still apply.
- Beyond 125 m from the camera, a baked scenery group with parts, such as Bryson Coal Dealer, has one square marker for the whole group, as a grade-crossing setup does. At 125 m or less, each part appears separately.
- Object and group frames now follow their model. A frame of several parts, such as the gold frame of `Bryson Coal Dealer`, lies along its parts, even when the group root stands at an angle to them, so it no longer covers ground and objects beside the group. A crossing pad is framed along its track instead of at an angle to it. A group frame no longer stretches to the position of an object that stands apart from its own parts, and a group switches between its parts and its one marker by the distance to the box it frames. A tilted object keeps a frame that turns with it. A container whose objects stand far apart, such as `Signs` at Ela or `Bryson Signs`, no longer has one frame across the map, so clicking an empty spot during a world choice finds no candidate.
- Object frames no longer change with camera distance. A part hidden by the game at a distance still counts for its object's frame. A static-batched building part counts once it has been shown with the patcher's markings since the map loaded. The square marker stays at the middle of the framed box as you zoom and turn the camera, even when that point is outside the view. A crossing pad is framed whole. A crossing controller's frame surrounds its whole grade-crossing setup's masts with their gates, bell, and pads, rather than one mast. It leaves out whistle signs and detection spans.
- The inspected object shows its gold frame and its square marker without a world label, at any camera distance. Its detected problems show in the panel.
- You can move, rotate, or disable mileposts and set, replace, or detach their track binding in the native map editor or through `scene-patches.json` (`milepost-v1`, target component `Helpers.MilePost`). Placement and binding are separate: moving a post keeps its binding, and changing the binding does not move it. The model, mile value, prefix, and displayed text stay unchanged, no mile value is recalculated, and the game's origin cache keeps its entry. If any of these change, the edit fails and the post is restored. Mileposts are no longer inspection only. Scene patch files with a milepost modification require patcher 0.5.0.
- The native map editor refuses a scene patch file whose `sourceMap.mapId` names a map patch. The game skips such a file in a save because a map patch is never the loaded map or one of its layers. The diagnosis names the bottom map layer to use instead. Scene patch editing still works inside a map patch and names the bottom map layer.
- A failed edit in scene patch editing now reports what happened: `refused` when nothing changed, `failed and was undone` when the object was restored, or `failed; cleanup is incomplete` with the position, activity, binding, coverage, or leftover spans that could not be confirmed. Each message gives a correction, and the new **Guide** button in the footer opens the guide for the failed operation. While cleanup is incomplete, the footer shows what remains and further edits to that object report `is blocked by incomplete cleanup`. **Recheck** compares the object with the scene patch file, removes leftovers from the failed attempt and keeps what the file names. Once they agree, the object accepts edits again. Runtime failure reports also name the state left by an incomplete cleanup.
- You can move, rotate, disable, and restore individual parts of baked scenery groups, such as a sawmill jetty or station lamp, in the native map editor and through `scene-patches.json` (`baked-scenery-part-v1`, target component `UnityEngine.Transform`). Each listed group's parts appear in the **Baked scenery group** family, named with their group, for example `Whittier Saw Mill / Jetty`. The group and its other parts stay as they are. A part with a fixed placement keeps it when its group moves later, including during a gizmo drag. **Remove modification** returns the part to its place relative to the group or the part above it. A part moved outside the sphere of a culler above it keeps its own culling sphere, so it shows at any distance from its group, and that culler keeps its radius. Siblings with the same name and LOD group levels are not listed as parts. Scene patch files with a part target require patcher 0.5.0.
- You can move, rotate, disable, and restore whole baked scenery groups, such as platforms, lamps, signs, and small buildings that the native map editor does not edit, in the native map editor and through `scene-patches.json` (`baked-scenery-group-v1`, target component `UnityEngine.Transform`). The new **Baked scenery group** family lists one entry per group root below `World`. Everything below the root moves with it, culling and colliders follow, and the activity of the parts stays as it was; these groups are decorative. Groups that hold game logic, rail bridges outside Ela, and the crossbucks of unprotected crossings are listed as inspection only with the reason. Track spans the game builds from operations data and everything below the CTC roots are no longer listed. Scene patch files with a baked scenery group target require patcher 0.5.0.
- Beyond 125 m from the camera, a grade-crossing setup has one square marker for the whole setup. Within 500 m, it also has one object frame around its visible objects. Click the marker to open a list of the setup's objects next to the pointer, then choose an object and click **Confirm** to inspect it. The list excludes detection spans, which the controller manages; they remain in the outliner as inspection only rows. At 125 m or less, each object appears separately. Whistle signs appear separately at every distance.
- A crossing controller reports a problem if one of its circuit spans refers to a track segment that no longer exists. The message identifies the circuit and span. To repair it, open the controller's **Connections** tab and select tracks for the circuit or detach it.
- An object frame is one box. An object of several parts is framed by one box around all its parts, turned with the object, instead of the combined outline of its parts; the frame of a grade-crossing setup is one box around all its objects, turned with the crossing. On sloping ground the bottom of the box lies at the lowest ground under the object, so the frame stays one box instead of following the slope.
- The patcher reads a scene patch file's `formatVersion` before anything else. A scene patch file whose version is missing, not the number `1` or newer applies none of its modifications, also when the rest would read as format version 1; the other mods' scene patch files still apply, and scene patch editing protects the scene patch file from overwrite.
- When the edited mod's scene patch file is protected, the session details show each problem with its JSON path, lines, the text there, and the expected value, with links to the format reference and the recovery guide. **Read again** adopts a scene patch file you corrected outside the native map editor and applies its modifications at once, without writing the file. **Start fresh** copies the original byte for byte to a verified `scene-patches.json.backup-<id>` and lets Save replace the original with an empty scene patch file. Both are reviewed and confirmed first.
- The game's Log window heads a scene patch row with the supplying mod's `Data/scene-patches.json` followed by `Railroader Scene Patcher`, instead of repeating the patcher's name. A failure of a modification whose dependency is missing names the dependency and the object.
- Scene patch editing refuses to remove a modification, also through **Clear activity** or by clearing its last crossing-coverage entry, while another modification names it in `dependsOn`, and names those modifications. An edit of a modification that does not take effect because a dependency is missing, fails, or forms a cycle is refused with that reason instead of being reported as applied.
- A track marker or crossing pad that holds a duplicate marker ID, such as `Mg6m` and `Mkft` in the base-game map, starts its dependencies with that marker ID, followed by every holder with its activity and the registration it has under the marker ID. The game removes a registration by marker ID from every holder, so an activity, binding, or track-following edit of a holder is refused before it changes anything, with a message that names the duplicate marker ID and every holder instead of a registration error and advice to reload. At load, a modification that would make such a change fails with the same explanation, and the scene patch file's other modifications still apply. Fixed placement of a holder stays editable. An active generic track marker that can take a replacement ID shows the problem with the repair offered; crossing pads and other kinds show the explanation only. An inactive generic holder, such as the yard limit that holds `Mg6m`, offers the repair too, and its **Detected problems** section says that it has no problem while it's inactive instead of `None detected`.
- A refusal in the message area reads as the action group followed by plain sentences, such as **Activity** with `Enable refused. The inspection was cleared before the request ran.`, without a second label before the reason.
- Starter placement markers now have their own **Starter placement** family in scene patch editing. A new-game setup uses these markers' track locations to place its starting cars. Each marker used by an active setup appears once, with all setups and car placements that use it, the cars in each cut, and whether they start as a wreck. An empty binding or missing segment appears as a problem even if the marker is disabled, because the game still reads its location. A gold marking shows the inspected marker's track point, and **Focus** moves the camera there. Markers used only by inactive setups are no longer listed.
- You can place a starter placement marker on the track, so a new company game on your map starts with its cars where you intend. On the **Connections** tab, click the track and confirm it to fill the track location, then click **Set**. The world shows the track point as the front of the car cut and the track the cut stands on from there. Before anything changes, the patcher checks the whole cut, with the cuts of the setup's other placements, by the game's own placement rule, and refuses a missing or ambiguous segment, a distance outside the segment, a detach, and a marker that no car placement or several read, each with the reason. Native Undo and Redo, **Clear location**, **Remove modification**, and failure restoration return the marker's earlier track location. `Data/scene-patches.json` stores it as `starterPlacement` with the setup and the track location, and Save raises the dependency to patcher 0.5.0.
- You can choose whether a cut of starting cars appears as a wreck in a new company game on your map. On a starter placement marker's **Connections** tab, the **Start derailed** checkbox under **Starting cars** shows the current setting and lets this mod override it. The checkbox is unavailable if the patcher cannot read the new-game setups, or if no car placement uses the marker or more than one does. Its tooltip explains why, and the patcher refuses the edit for the same reason before changing anything. Native Undo and Redo, **Remove modification**, returning the checkbox to the map's setting, and failure restoration can restore the earlier wreck setting. `Data/scene-patches.json` stores the value as `wreck` inside `starterPlacement`, after the track location. Save raises the patcher dependency to 0.5.0.
- The outliner lists its objects in one tree, in the alphabetical order of their names. The tooltip of a control that cannot be used gives its reason after **Unavailable:** as one plain sentence, without a second label such as `Not editable:`.
- A new scene patch file created by scene patch editing names the edited map definition's bottom map layer as its scene target map, or the definition itself if it has no map layers. For a map layered on `rr/bushnell-whittier`, the file applies to the mod's own map and to a save of the base-game map, where the mod's native changes arrive through its map-changing script or map patch. **Copy ID** names the same scene target map. An existing scene patch file keeps its scene target map, even on Save. To apply a scene patch file only on your own map, set `sourceMap.mapId` by hand. If the edited mod's scene patch file cannot be read, **Copy ID** is unavailable and its tooltip gives the reason.
- An edit in scene patch editing that writes a position or rotation keeps the text of every axis whose value equals the scene patch file's value at the precision the game stores, so changing one axis no longer rewrites the others as longer numbers read back from the game.
- `modifications` in `scene-patches.json` is an object keyed by modification ID, and a modification has no `id` member. `relationships.crossingCoverage` is an object that holds `circuits`, keyed by the ID of each circuit's island span from the map, and `additions`, keyed by addition ID. The order of keys and members has no meaning: the patcher applies modifications that `dependsOn` does not order in the ordinal order of their keys. A scene patch file whose `modifications` is an array is rejected and protected from overwrite; rewrite it by hand in the keyed shape. A modification that still carries an `id` member fails with a message that names its key, and the other modifications still apply.
- A Save writes the scene patch file in one canonical order and keeps the literal of every number it does not replace. The scene patch file counts as saved when its content equals the file's content, whatever the order of members, the spacing, or the way a number is written, so reordering or reformatting the file by hand is not an unsaved or outside change and does not turn the Stale lamp on. A Save without a patch change leaves the file's bytes as they are.
- A Save that fails while writing `Data/scene-patches.json` or `Info.json` leaves the previous file intact, so your edits stay in memory and Save can be retried. Each file is written completely beside the original first, as a `.saving` file, and only then replaces it.
- When a player's game loads the same map again, for example on reconnect or same-map re-entry, the patcher checks each modded object and added object instead of relying on an applied flag. Applied modifications are not duplicated, an object the game keeps keeps its state, a rebuilt object gets its modification as new, and only the patcher's own leftovers for the old object, such as detection-addition spans, are removed. A cleanup failure is reported on that player's game only and retried at the next load. In single-player, loading the same save again rebuilds the modded objects and added objects, and each modification is applied once. Live reconnect has not been tested yet.
- When the patcher's state ends while the map stays loaded, for example when mods are reloaded or unloaded without unloading the map, the patcher first returns patched grade crossings to their native detection and removes its spans, so a new patcher state applies each crossing-coverage modification once instead of refusing it. A crossing that the patcher could not return to native detection is refused for editing until the map reloads. This has not been tested in the game yet.
- In multiplayer, the host and every client apply the scene patches from their own installed mods to their own scene when their world loads, and each checks the map, target, and capability locally. A failure on one player's game is reported there only. The patcher adds no synchronization or admission check; Railroader's own checks of required mods and versions still decide who can join. Live host and client sessions with this release have not been tested yet.
- The patcher applies the scene patches of several loaded mods in Railroader's load order. A mod applies only when it declares the patcher dependency and its scene target map matches the loaded map or one of its layers. When mods change the same existing target, an informational game message names the object and the mods; it reports a possible incompatibility, chooses no winner, and does not stop application. A failure in one mod's scene patch file leaves the other mods' work in place.
- You can remove a marker repair even when its original track is missing. Removal restores the captured native reference and warning; Undo and Redo recover the repaired and broken states without changing unrelated warning rows.
- You can make an object follow an explicitly selected track segment location or endpoint, in the native map editor and through `placement.mode = "trackFollowing"` in `scene-patches.json`. The object keeps its position and orientation relative to that track; it moves with the track in the native map editor and is placed from the track's current pose on every load. In the native map editor the object also follows a track that turns by less than half a degree. Scene patch files with a track-following placement require patcher 0.5.0.
- Generic track markers whose activity follows a track group can be edited. Rebinding moves the group subscription with the marker. An explicit disable holds the object inactive when the group is enabled later; without it the group keeps switching the object. Clearing the mod's activity value or removing the modification returns the object to its group. A modification that omits `active`, in the same scene patch file or in a later mod, and a gizmo preview leave an explicit disable in place. Scene patch files with an `active` value on a track-marker object require patcher 0.5.0.
- Generic track markers inside a grade-crossing setup, such as whistle signs, can be edited like other Generic markers: binding, placement, track following, and activity. The crossing pad and the crossing's own markers keep their own operations.
- Gizmo rotations of less than half a degree are now kept. Previously, they completed without a modification or history operation.
- Runtime failures produce structured game warnings with the supplying mod, operation, target when resolved, error, and patcher and game versions. For eligible dependency-free relationship-only marker repairs, the patcher tries repair before the game's native marker check. If that route is unavailable, it removes only the exact current warning row after a successful operation and separate verification of the binding and dependent state. Reporting adds no scene patch file, schema, or capability requirement.
- Runtime diagnostic text no longer repeats the source prefix. The originating source remains available as the native warning originator.
- You can add detection for explicitly selected extra tracks at an existing grade crossing, in the native map editor and through the `additions` object of `relationships.crossingCoverage`. An addition has an ID that is unique in its mod's scene patch file and is its key in `additions`, and the tracks and area of its three spans. The patcher builds one circuit with its own spans for it on every load, reuses it on a repeated load, and removes it when the entry is deleted. Native circuits keep their coverage.
- You can correct the detection coverage of existing grade crossings, in the native map editor and through `relationships.crossingCoverage` in `scene-patches.json` (`crossing-coverage-v1`). Each circuit, named by its island span from the map, keeps its coverage when omitted, covers explicitly selected tracks, or is detached. The map's own detection spans stay registered and unchanged, so a still-valid old route stops triggering the crossing; other circuits keep working. Scene patch editing previews the effect on every circuit before applying. Scene patch files with crossing coverage or a crossing-coverage target require patcher 0.5.0.
- You can set or replace the track location of crossing pads in the native map editor and through `relationships.trackMarker` in `scene-patches.json` (`crossing-pad-v1`). The pad's graph registration follows the binding, and the game's pad generation rebuilds the pad geometry and culling at the new location; Undo, Redo, removal, and failed edits generate the pad again from the restored location. Pads cannot be detached; disable them to hide them. Scene patch files with a crossing-pad modification require patcher 0.5.0.
- The Scene Patcher window opens from an icon in the top-right button strip, below the Map Editor window. An outliner with search, All, Problems, and Changed filters, one tree in the By category or By place view, and a resizable column sits beside an inspector with the Object, Placement, Connections, and Changes tabs and a fixed footer for actions and results. Each region has context help behind a `?`.
- You can add lights and gates to existing grade crossings, in the native map editor and through `relationships.crossingEquipment` in `scene-patches.json`, an object keyed by equipment ID. The patcher copies a device already loaded in the crossing's scene when its lamps and gates work through the crossing controller's lights and gates keys (`crossing-light-gate-v1`), whatever its model; scene patch editing lists ineligible devices with their reason. The controller drives the copy, which joins the crossing's culling. Each addition has a persistent ID scoped to its mod; repeated loads and Undo/Redo keep one copy per ID. Scene patch files with crossing equipment require patcher 0.5.0.
- You can add bells to existing grade crossings in the native map editor or through `relationships.crossingEquipment` in `scene-patches.json`, using `crossing-bell-v1`. Each bell has its own player beneath the crossing controller and rings when the controller rings its own bell. It can use any sound from a bell definition in the content library. The editor lists every bell definition and explains why any definition is refused. Each bell loads and keeps its own audio, then releases it on removal. If the audio fails to load, the bell stays silent and produces one warning that identifies it. Bells have persistent IDs scoped to their supplying mod. Repeated loads and Undo/Redo keep one player per ID. Scene patch files with crossing bells require patcher 0.5.0.
- Scene patch files with a relationship, a track-marker target, an Ela bridge modification, or a board other than the Sylva location sign require patcher 0.5.0. Previously, a relationship or a track-marker target required patcher 0.4.0, and the other two required patcher 0.3.0.
- The patcher's lines in the Player log are now only the warnings and errors that the game's **Log** window doesn't already show. A normal session, with load, edit, and save, writes no information line. Load steps, edit results, saves, and diagnostics appear in the Player log only while **Debug logging** is on.
- **Debug logging** is a new option in **Preferences > Mods > Scene Patcher**. It adds that detail to the Player log, is off by default, takes effect at once, and is stored in the patcher's `settings.json`. Turn it on before you reproduce a problem you report, and off again afterward.
- A mod that has a scene patch file but doesn't list the patcher under `dependencies.required` in its `Info.json` now produces a warning in the Player log.
