# Marker group placement preparation

This preparation supports [track-relative placement and group precedence](https://github.com/CrankyAnt/RailroaderScenePatcher/issues/24). Boot02 tested manual rebind, placement, group toggles, explicit disable and restoration. Boot03 tested an armed automatic application during editor fixture load. See the [Boot02 manual report](../Evidence/Boot02/MarkerGroups/Report.md) and [Boot03 automatic report](../Evidence/Boot03/MarkerGroups/Report.md). The moved placement was not visibly observed, and ordinary-save reload was not tested. The issue remains open.

## Sources and static inspection

The [retained lifecycle inspection](https://github.com/CrankyAnt/RailroaderScenePatcher/blob/3e5970722bb278cbbaee003300ada6ce916df702/Research/ApplicableLifecycleStatic.md#group-observation-and-restoration) reports the conditional subscription and placement paths. In particular, `Track.TrackRelativePosition.TryApply` can unsubscribe and observe the current group after a failed placement attempt; an absent marker returns earlier. `Track.TrackMarker.Location` changes logical binding without itself moving the target or updating graph registration. The subscriber's unsubscribe path uses the current shared graph, so graph replacement complicates cleanup. These are static findings, not observations of this fixture.

Local read-only inspection of the installed `Railroader.dll` with Mono.Cecil confirmed method-call references in `Track.TrackRelativePosition.TryApply` to `MoveTransform`, `UnsubscribeFromGroupEvents`, and `ObserveTrackGroup`; `ConfigureAndApply` calls `TryApply`, and `OnDestroy` calls `UnsubscribeFromGroupEvents`. The original inspection above supplies the conditional behavior, which this call-reference check alone does not prove. The installed Railroader 0.6.2 experimental build 26335745 assembly SHA-256 is `8E9ACFD583C1DA79655C970773D42F2179E999F62DC36A3C6BC3A7B94C27A91E`. That hash does not identify scene assets.

The [retained group experiment](https://github.com/CrankyAnt/RailroaderScenePatcher/blob/3e5970722bb278cbbaee003300ada6ce916df702/Research/ApplicableProbeNext/ApplicableProbe.cs) toggled `sy-db` and installed a temporary explicit-disable callback. It did not rebind a marker to a different group. The [continuation report](https://github.com/CrankyAnt/RailroaderScenePatcher/blob/3e5970722bb278cbbaee003300ada6ce916df702/Research/ApplicableOperationsContinuation.md) does not resolve this marker question.

## Prepared trial

The opt-in `MarkerGroups` probe has manual focus, capture, apply and repeat, group toggle, explicit-disable and restore controls. Focus is available only before capture; wait for the origin to settle before capturing. It requires the scene-operations map, T-46 marker `Mdow` in `sy-db`, a valid T-93 location in `na-an`, both groups enabled, one native subscriber, one matching marker registration, and an active target. The destination uses the other marker's resolved location. It does not modify that marker. The trial captures the original location, placement settings, parent and root pose, active state, callback count and last-apply value. It logs descendant poses, group subscriptions and registrations at each phase. Registration checks compare object identity, marker ID, segment bucket and the location segment identity, distance and end against the expected binding. The expected count follows marker activity. It configures a nonzero offset and angle with terrain snapping disabled, then reobserves the original group on restore. It tests old and new group toggles both before and after restoration. Repeat can be invoked while explicit disable is active. Group toggles affect all objects in those groups.

The probe requires the first -homedir argument to name `C:\TMP\RailroaderMapResearch\RuntimeHome` and its mod directory to be `C:\TMP\RailroaderMapResearch\RuntimeHome\Mods\MarkerGroups`. Run it sequentially with other T-46 probes. The probe rejects a changed graph, map, loaded scene, parent or origin and reports cleanup failure rather than claiming recovery. Its unload handler removes its own callback from the captured graph, records a dirty unload, and drops all captured references; it cannot restore a replaced world. Its checks do not prove exact restoration of all group members, child transforms, downstream culling or caches. Telemetry does not prove visible placement. Review it before runtime use. A failed apply may have already changed native subscriptions, so restore must still be attempted; if the guard rejects restoration or any check fails, discard the session without saving.

The native-loader manifest is `Info.json`. The focus revision was built before Boot02. The .NET SDK 10.0.403 build against the installed managed assemblies succeeded with zero warnings and errors, writing outside the checkout. The DLL at `C:\TMP\MarkerGroupsBuild\bin\MarkerGroups.dll` has SHA-256 `6DDCD4205180BCEECCB3B7DDD9B45DE8C2BCC110CF3C6A800A60A32EB2D94C87`. The current batch [build manifest](../BuildIdentity.json) may describe a later build; the frozen [Boot02 build identity](../Evidence/Boot02/BuildIdentity.json) and [Boot03 build identity](../Evidence/Boot03/BuildIdentity.json) record the pack and fixture identities for those trials. Neither manifest identifies all fixture or game assets. Probe logs may contain game-derived state and must be reviewed before sharing.

## Remaining work

Boot03's wrong-map readiness wait timed out without mutation. After rearming for the custom fixture, the probe observed five seconds of stable readiness and automatic application returned true. A manual repeat returned true. With explicit disable set, the repeat briefly activated the target and registered it before the probe restored the disabled state. A later guarded group-toggle request was refused before mutation. These observations do not establish uninterrupted disable during repeat.

Native restoration with the original placement configuration returned false. The probe then wrote the captured root pose directly; the logged binding, placement settings, active state, registration and group observation matched the recorded baseline at displayed precision, with a small local-coordinate difference at the last displayed decimal. This is not proof that native placement succeeded or that all dependent state and group members were restored. The cause of the false return is not established. The moved placement was not visually observed. The report does not cover ordinary-save reload or persistence. Runtime work requires the exclusive game lease, isolated test environment, expected fixture and a stopped game for installation. Results for this one component do not establish behavior for other marker consumers.
