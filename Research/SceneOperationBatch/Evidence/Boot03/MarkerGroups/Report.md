# Marker groups: Boot03 automatic trial

The [selected telemetry](SelectedTelemetry.txt) records one armed automatic application in the scene-operations editor fixture, followed by manual repeat, explicit-disable and restoration steps. It supports [Test track-relative placement and group subscription changes](https://github.com/CrankyAnt/RailroaderScenePatcher/issues/24). The distant moved placement was not visually observed. This is one fixture editor load, not an ordinary-save reload or proof of persistence in a save.

The first arm preceded the default editor load. The readiness wait timed out without attempting mutation. The operator rearmed before opening the custom fixture. The probe logged a five-second stable-ready period, captured the baseline, and applied once. Baseline marker `Mdow` had its `Stvw` binding, one matching registration and one native subscription observing `sy-db`. Automatic application returned true, moved the logged root pose, rebound it to `Sn9f`, and recorded one matching registration and one native subscription observing `na-an`. A manual repeat returned true and retained the same logged pose to displayed precision. The five-second sample is a bounded guard, not proof that the origin cannot change later.

The temporary explicit-disable callback fired on `na-an` activation and the target remained inactive with no registration at the subsequent snapshot. Repeating application while explicitly disabled temporarily produced an active target with one registration before the probe restored the disabled state and removed the registration. After this repeat the operator requested the ordinary group-toggle control. Its guard rejected the request while explicit disable was active, logging `toggle ERROR`; inspection of the frozen probe source shows this guard runs before the group mutations. This is a refused control, not evidence that a group mutation failed. The operator then used the explicit-disable control again. The callback fired on the next `na-an` activation and the target remained inactive with no registration. These snapshots establish the tested callback ordering, but not uninterrupted disable during repeat.

**Restoration has a material limitation.** The probe logged `restored apply=False` when it called the native placement operation with the original terrain-snap settings. It then wrote the captured root pose directly and logged the original binding, placement settings, active state, one matching `Stvw` registration and one native subscription observing `sy-db`, with its own callback absent. The logged root pose matched the baseline at displayed world precision; a local coordinate differed in the last displayed decimal. Restored group toggles and the final registration check passed. The UI nevertheless reported restoration complete because the probe's subsequent checks do not require the native apply return value to be true. The cause of that false return is not established here. Direct pose restoration and matching registration do not prove successful native terrain placement, bitwise equality, all dependent state, or restoration of every other group member.
