## Probe operation and observations

The probe creates a Unity behaviour on world load and polls for the editor controller. It logs controller identity, subscription success and events to `EditorProbe.log` beside the diagnostic pack manifest. It offers explicit rescan, scene-object focus and segment-endpoint focus buttons. A scan reads selected scene markers including inactive ones and the named board, recording world and game positions, marker serialized location, current segment existence, endpoints and a fresh graph location calculation. It does not use the marker's cached `PositionRotation`. Each scan has a numbered log entry. The view stays unchanged until an explicit scan: event notifications are logged but do not refresh it automatically. Camera focus uses the target object's current transform, converts it to game coordinates and asks for the Strategy camera; it does not change native selection. Duplicate matching objects cause focus to fail and log an exception. Boot04 exercised scans, an endpoint-focus request and event subscriptions during graph edits; broad reflection and lifecycle behavior remain untested.

1. Enter the disposable map editor. Record load order, controller identity, successful or failed subscriptions, window visibility and initial scan. Check that Mjd8 points to missing Sozu, M5pp resolves to Shuo with its track point physically displaced from its board, and the independent board exists. Compare segment and node positions with native editor information and inspect scene objects independently. Marker-to-track offset can be intentional, so establish incorrect placement against the original geometry or known fixture change rather than treating any nonzero offset as an error. If any precondition fails, stop and report the exact observed state; no validated repair procedure exists for this renamed copy. Do not treat it as a runnable fixture until its mapData resolution and all three conditions are confirmed.
2. Use each focus button. Record the requested game coordinates, the camera destination, floating-origin state and whether native selection changed. Test again after an origin shift if feasible. Camera movement is not proof of native selection.
3. On the disposable fixture delete a referenced segment, change geometry of a surviving referenced segment, then undo and redo. For each action record the previous display, events and their order, a fresh independent native graph inspection, and an explicit probe rescan. Compare segment existence, endpoint positions, curve point and scene pose. Note event gaps and duplicates, including during drag preview. Explicit scans measure only when invoked and do not establish automatic freshness.
4. Exit the editor and inspect unsubscription and destruction logs. Re-enter and repeat a scan. If available, disable the temporary mod and verify no callbacks or view remain. Record callback order and duplicate subscriptions. Save only into the isolated fixture if required; do not touch the normal save.
5. Stop the game. Remove only the two uniquely created packs, restore the original preference and mod selection, and verify recorded state and hashes. Release the orchestrator's lease. Retain authored tooling and publishable observations, not game assets or binaries.

The probe's graph scan and its displayed text share an implementation. It is not an independent oracle. Native graph inspection and a separate scene observation are required to validate its results. It has not established complete event coverage, identity stability, all focus cases, repeated cleanup, or graph refresh after edits. A failed fixture or probe is incomplete evidence, not proof that editor integration is impossible. Issue 14 remains open until the actual observations satisfy its criteria.
