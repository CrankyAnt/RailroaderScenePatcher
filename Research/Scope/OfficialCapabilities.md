# Official capabilities relevant to a base-map rework patcher

Research checked 2026-11-07. The official documentation describes 0.6 experimental and is mutable; it is not a version-pinned specification. No game or mod behavior was tested for this note. The initial 0.6.0 experimental launch was 2026-10-27; use that date as a discovery cutoff for new 0.6 mods, not as proof that a later upload is compatible. The release index dates 0.6.1 to 2026-10-28. [Release index](https://docs.railroadergame.com/release-notes/), [launch announcement](https://community.railroadergame.com/t/railroader-0-6-0-experimental-is-now-available/147), [experimental branch](https://docs.railroadergame.com/experimental/).

The question is what may need repair when a mod moves or deletes base track. A documented editor limitation alone does not prove a broken reference, a need for a shared framework, or that a DLL is necessary. The official map guide explicitly says building on the base map is not yet officially supported, because scene objects remain outside map data and later migration can break layers. [Map modding](https://docs.railroadergame.com/modding/map-modding/).

## Native patch semantics and limits

`Scripts/Data.rl` runs `modifyMap` each time map JSON loads, after parsing and before deserialization. `map.merge` recursively merges objects, deletes keys with null, replaces arrays in full and overwrites scalar values. `map.modify` mutates the parsed dictionary directly. Earlier dependency-ordered pack changes are visible to later packs, and later changes win on the same field. A throwing `map.modify` handler discards its changes and later packs continue. These mechanisms operate on map JSON; the documentation does not establish that they can mutate scene-only objects. The editor does not run Data.rl, so editor previews do not include these patches. [Data.rl](https://docs.railroadergame.com/modding/data-rl/), [map modding](https://docs.railroadergame.com/modding/map-modding/).

Relay track queries expose marker lookup, segment lookup, route and distance operations. Distance can fall back to an approximation when no route connects locations, so a numeric answer alone does not prove connectivity. World exposes limited signal operations and map feature toggling. None of these descriptions proves an API to move scene objects or rewrite their references. [Track](https://docs.railroadergame.com/modding/relay-api/railroader/track/), [World](https://docs.railroadergame.com/modding/relay-api/railroader/world/).

The supported DLL contract is the small `Railroader.Modding` contract; internals outside it may change without notice. Do not label any family DLL-only without implementation evidence. The migration guide says older third-party DLL map mods need changes for 0.6 and notes unsupported advanced trackwork and custom industry behaviors. [Modding overview](https://docs.railroadergame.com/modding/), [migration guide](https://docs.railroadergame.com/modding/migrating/).

## Version and evidence limits

The 0.6.1 notes mention new RepairTrack and Interchange components defaulting to the `*` car filter. The 0.6.2 notes describe changed interchange internals so equipment purchases no longer require an InterchangedIndustryLoader. Neither item establishes that existing track references are repaired automatically. [0.6.1](https://docs.railroadergame.com/release-notes/0-6-1/), [0.6.2](https://docs.railroadergame.com/release-notes/0-6-2/).

The known-issues list is explicitly incomplete and planned work can change. The docs do not supply a complete object/reference schema, a per-object storage inventory, or proof of which base-game objects fail after a given edit. Inspect installed data and code, then reproduce representative moves and deletions before deciding project scope or naming. [Known issues](https://community.railroadergame.com/t/experimental-faqs-known-issues-planned-improvements/129).
