# Candidate scene object families

Read-only inventory of installed Railroader 0.6.2. Primary sources are the installed `Railroader_Data/Managed/Railroader.dll`, inspected with Mono.Cecil, the installed `Railroader_Data/level4` scene as documented in [PositionControl.md](PositionControl.md) and [SylvaMarkerComparison.md](SylvaMarkerComparison.md), and the official [map modding guide](https://docs.railroadergame.com/modding/map-modding/). No game, mod, or save file was changed. Assembly metadata establishes code paths, not that every type occurs in the scene or is editable through a particular editor view.

| Family and evidence | Relationship and proposed isolated test |
| --- | --- |
| Whistle signs and crossing pads with `Track.TrackMarker` | Proven scene marker failures include Ela crossing pads M5ib and Muef. The visible Sylva whistle sign M5pp retains its scene placement when its logical track geometry changes. `TrackRelativePosition` can target a separate transform, offset and angle. Delete the referenced segment in a disposable map, then rebind, apply placement and compare marker registration, model pose and train behavior. Test disabling separately, including registration cleanup. Sources: [ScopeInventory.md](ScopeInventory.md), [SylvaEditorLookup.md](SylvaEditorLookup.md), `Railroader.dll` types `Track.TrackMarker` and `Track.TrackRelativePosition`. |
| Standalone location signs | The scene's `World/Signs/Loc: Sylva Int` has a visual hierarchy and `CircleMapMask`, but no marker or track-relative positioning. Move its root to a known destination and check text, terrain mask, culling, reload and floating-origin shift. Disabling must also check the mask; hiding a renderer alone is not equivalent to disabling the object. Scene identity and components: [PositionControl.md](PositionControl.md). |
| Mileposts | `Helpers.MilePost` owns a `TrackMarker` reference, mileage and origin-related data; it unsubscribes from marker location changes on disable. This establishes a separate mileage behavior to test, not a proven broken origin chain. Rebind and move an identified scene post, then check displayed mileage and other posts sharing its origin before and after reload. Source: `Railroader.dll`, `Helpers.MilePost`. |
| Protected grade crossing circuits | Candidate beyond individual crossing markers. `Track.Crossings.GradeCrossingController` contains `circuitSets`; each `CircuitSet` references `TrackSpan` objects `approachA`, `island` and `approachB`. `UpdateCircuit` checks cars on the island and estimates arrival on both approaches; the controller has gate and light thresholds. Verify an actual scene instance and its ownership before treating this as scene-backed. In a disposable map, delete an endpoint, record diagnostics and behavior, then repair or replace the correct circuit references. Exercise trains from both directions, occupancy, lights, gates and bell; do not infer operational correctness from visual movement. Compare explicit controller disable and object disable separately. Source: `Railroader.dll`, `Track.Crossings.GradeCrossingController`, nested `CircuitSet`, `UpdateCircuit` and `OnDisable`. |
| Scene bridges and other retained scenery | The official map guide states the editor cannot edit some original scene objects, including bridges, signs and mileposts. A graph segment's bridge properties do not establish that an inherited scene bridge is repositioned. Identify one bridge in the installed scene, change its adjacent track in a disposable map, and check physical clearance, collision and visual alignment after moving or disabling its scene root. No specific bridge component or successful relocation was established. Source: [map modding guide](https://docs.railroadergame.com/modding/map-modding/). |
| Scene track-group-linked visuals | `TrackRelativePosition` includes `targetActiveFollowsTrackGroup`, a target transform, and group-change handling that sets target activity from enabled group IDs. This is a code-level dependency; an affected scene instance has not been identified. On an identified instance, rebind to a different group and toggle each group's state, checking target activity and whether old subscriptions remain. Disabling or moving the visual without checking progression can leave inconsistent behavior. Source: `Railroader.dll`, `Track.TrackRelativePosition`. |

## Signals, excluded from V1

Scene CTC blocks can own child `TrackSpan` components; their endpoints can fail to resolve after graph edits. `CTCAutoSignal` separately has block references, and signal placement does not redefine blocks, routes or interlocking. Test a scene span endpoint repair and a signal relocation as separate cases, including switch positions, occupancy and aspects. A real affected instance and successful runtime repair remain unproven. See [GameReferenceFamilies.md](GameReferenceFamilies.md) and [PositionControl.md](PositionControl.md). Signals are not part of the proposed V1 object scope.

## Test boundaries

Use a fresh disposable map, save and separately toggled probe. Record build, object identity, original reference and pose, changed segment and observed behavior. Native OpsDTO industry and passenger spans are loaded from map data and do not establish scene ownership. The installed passenger stop class and DTO alone do not prove a scene-only passenger-stop repair need. Avoid changing normal saves or original packs. A scene object existing in code or a proposed test does not establish a runtime repair API or a safe general-purpose disable operation.
