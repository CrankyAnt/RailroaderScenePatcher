# Editor test matrix

Checked 2026-11-07. This is a proposed controlled test plan, not a record of tests performed. The [official map guide](https://docs.railroadergame.com/modding/map-modding/) describes the experimental editor and may change without a version pin. It warns that layering on the base map is not officially supported because some elements still reside in a Unity scene. A documented category is not proof that a particular base instance is editable.

## Evidence and method

“Documented” means the official guide describes the category. “Observed” refers to prior work in [ScopeInventory.md](ScopeInventory.md) or [GameReferenceFamilies.md](GameReferenceFamilies.md), not a new test here. “Unverified” means the particular operation or instance still needs a test. A failure to select an object is evidence about that instance and editor build, not proof that every similar object is scene-owned.

Use a disposable layered map and a fresh sandbox session. Record exact game build, map and pack versions, object identity and coordinates, initial and resulting references, screenshots, saved map-data diff, reload result, and new log messages. Test each operation independently against the same baseline. Physical relocation means changing a visible object's world position. Logical rebind means changing its track location or span endpoint without assuming that its visible object moves. Disabling or hiding is optional and must be measured separately. Do not infer a successful rebind from appearance alone. The editor does not apply [Data.rl patches](https://docs.railroadergame.com/modding/data-rl/), so verify those separately in a fresh game load if used.

## Representative controls and candidates

| Family | Evidence and scope | Minimum controlled test |
| --- | --- | --- |
| Track graph | Documented editable nodes and segments, switches, turntables and diamond crossings. This is the reference change, not by itself a scene repair. | Move one segment while preserving its ID, then separately replace or delete a segment in a fresh copy. Record IDs, geometry, saved data and dependent diagnostics after reload. |
| Water tower or column, other service structures | Built-in coaling, water and diesel structures are documented editable. The Sox water column was previously corrected in map JSON through the editor. Native control, not automatic helper scope. | On one identifiable water column, separately move the visible structure and change any offered track anchor. Inspect saved fields and reload. Record whether either operation changes the other; do not assume all instances expose an anchor. |
| Industry and track span | Operations and industry spans are documented editable. Prior code inspection identifies native OpsDTO spans as map-data-backed. Native control. | On one industry with a visible span, change one endpoint without moving the physical structure. Reload and inspect endpoint IDs and distances. Separately move the structure and check whether its span changes. |
| Props and retained scenery | Loaded prop definitions are documented placeable and movable. Some base scenery remains unported and cannot be edited. Individual ownership is unverified. | Move one editable placed prop as a control. Separately try selecting one retained base object next to altered track; record selection and save result without assuming it is a prop. |
| Sign or milepost and its marker | Signs and mileposts are documented as not editable. Prior work reproduced three Sox Ela scene marker failures and repairs; milepost position may use a marker. Visual relocation and marker rebind remain separate questions. | Identify one visible sign or milepost and associated marker only if identity can be established. Record editor selection. In an isolated reference test, inspect the marker's old and replacement location and its resolved position after reload. Observe the physical object separately. Optional disable requires its own test. |
| Road crossing equipment and associated marker | Road equipment must not be confused with editable diamond track crossings. Editor support for a particular crossing and the relationship between equipment and marker are unverified. | Inspect one road crossing beside the altered segment. Attempt selection of its equipment, identify any marker independently, and record physical position and logical location before and after the isolated track change. Do not infer marker type from object name. |
| Scene CTC block span | Prior code inspection found scene child `TrackSpan` components consumed by CTC blocks; a damaged endpoint has not been reproduced in this context. Candidate only. | If an identifiable affected scene span exists, record both endpoint references and a baseline log. Change one referenced segment in a copy and reload; capture any exact diagnostic. Do not treat an OpsDTO industry span as this control. |
| Signals and CTC | The guide lists signals and the CTC board as not editable. Scene signal-to-block references are distinct from track spans. Future extension, outside V1. | Defer mutation. If encountered, document identity, selection and baseline relationship only. A null-block warning alone does not establish that track editing caused it. |
| Bridges | Track segment bridge properties are editable; some base bridges remain scene-owned according to the guide. | Change bridge structure on one editable segment. Separately attempt to select a retained visible base bridge and record alignment and saved fields. Do not equate a segment property with movement of the scene bridge. |
| Passenger stops | Definitions are possible, but the official guide says they are not yet usable in game. A particular base stop's storage is unverified. | Inspect one stop's selectable fields and any span or location. Save and reload a sandbox definition; do not claim working passenger service from successful authoring. |
| Progression and construction groups | The editor cannot edit milestones or progression. Prior code inspection found group-ID references, not a demonstrated broken track location. | Record a relevant track group before and after a separate group edit. Inspect the milestone relationship only if identifiable; do not claim failure or repair without a reproduced effect. |
| Map icons, lakes and terrain details | Icons and lakes are listed as uneditable; individual trees and details are not editable, although land cover can be painted. | Inspect one map icon or lake and one individual terrain detail near changed track. Record selection and visual effect only; no track dependency is established. |

## Prioritized next tests

1. Establish the unchanged sandbox baseline and reproduce one known Sox Ela marker failure with its prior repair disabled. Capture its identity and reference, not merely the visible object.
2. Run the water-column and industry-span native controls. Separate visible relocation from anchor or endpoint changes and inspect the saved layer after reload.
3. Test one sign or milepost and one road crossing for selection and independent marker identity. Attempt a rebind only when the exact target and safe test route are established.
4. Inspect a scene CTC span only if an affected instance can be identified. Keep signals and CTC mutations for a future extension.
