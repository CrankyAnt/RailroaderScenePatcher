# Historical FUSE Ela passenger-stop warning

Research for [issue 20](https://github.com/CrankyAnt/RailroaderScenePatcher/issues/20), 2026-11-08. The warning and a matching FUSE source path are identified as historical provenance. The August incident belongs to an earlier game version and is outside the 0.6.x experimental investigation.

## Recovered message

The [original Discord message](https://discord.com/channels/795878618697433097/1275391753129562113/1541491926044516383), in the Moloch's Mods thread, was recovered through authenticated search by the issue investigation on 2026-11-08. It is dated 2026-08-24 at 18:58 Europe/Amsterdam. It contains the diagnostic `FUSE passenger stop id='ela' component='ela-house.ela' ignored invalid span binding(s): Pbhv. The stop will refresh again after graph rebuilds.` The surrounding report says a mod initially saw a valid passenger station and later no longer saw it after the warning. This sequence is a report, not proof of causation. The message does not identify exact game, FUSE or package versions or the source definition and endpoints of Pbhv.

The [original inventory](https://github.com/CrankyAnt/RailroaderScenePatcher/blob/4c00445b048adccb6920c238116d1f7e1e915db9/Research/Scope/ScopeInventory.md#discord-symptom-searches) had only summarized the search result. Git grep of that archive's Research tree for `span invalid` and `FUSE Ela` found only the summary. Public web searches did not recover the original; authenticated Discord search subsequently did. This supersedes the earlier unavailable-source finding.

## Matching primary source

The FUSE default-branch commit [1eeef152ec57066bb7a90e1ef6edb27f6018e690](https://github.com/F-U-S-E-E/FuseDevelopmentGroup/commit/1eeef152ec57066bb7a90e1ef6edb27f6018e690) was the latest returned by GitHub before the message time. This is a contemporaneous source comparison, not proof that the reporter ran that commit or a particular release.

In that commit, [`FusePassengerStopComponent.ResolveBoundSpans`](https://github.com/F-U-S-E-E/FuseDevelopmentGroup/blob/1eeef152ec57066bb7a90e1ef6edb27f6018e690/FUSE/Runtime/API/FusePassengerStopComponent.cs#L229-L269) contains the matching diagnostic. It inspects its `TrackSpans`, retains spans with non-null lower and upper locations whose segments both resolve, and lists invalid spans by ID or name. It deduplicates warnings by component, stop and invalid list. The message therefore matches this FUSE virtual industry-component refresh path. It does not itself say which endpoint failed, why it failed, or whether any other valid spans existed.

The same [component refresh](https://github.com/F-U-S-E-E/FuseDevelopmentGroup/blob/1eeef152ec57066bb7a90e1ef6edb27f6018e690/FUSE/Runtime/API/FusePassengerStopComponent.cs#L124-L227) creates or obtains a passenger-stop object, sets its spans from the valid subset, builds markers, refreshes its cache and rebinds station agents. It subscribes to graph rebuilds and retries while active and configured. This is static source behavior, not observation that the reporter's stop recovered or that a retry occurred.

[`IndustryAPI.ComponentApply`](https://github.com/F-U-S-E-E/FuseDevelopmentGroup/blob/1eeef152ec57066bb7a90e1ef6edb27f6018e690/FUSE/Runtime/API/IndustryAPI.ComponentApply.cs#L35-L48) resolves or patches definition span IDs into component `trackSpans`. The [FUSE schema notes](https://github.com/F-U-S-E-E/FuseDevelopmentGroup/blob/1eeef152ec57066bb7a90e1ef6edb27f6018e690/schemas/FUSE_JSON_SCHEMA.md#L397-L415) give `passengerStop` industry components with `trackSpanIds`; the [legacy converter](https://github.com/F-U-S-E-E/FuseDevelopmentGroup/blob/1eeef152ec57066bb7a90e1ef6edb27f6018e690/FUSE/Loading/FuseLegacyDataConverter.Components.cs#L18-L47) accepts `trackSpanIds`, `trackSpans` or `spans` and converts them. These paths establish possible serialized ownership, not which authored file supplied this particular binding or whether the original component was created or patched from other data. Pbhv's own span definition and supplying package remain unidentified.

A separate [`PassengerStop.OnEnable` guard](https://github.com/F-U-S-E-E/FuseDevelopmentGroup/blob/1eeef152ec57066bb7a90e1ef6edb27f6018e690/FUSE/Patches/FusePassengerStopInvalidSpanGuardPatch.cs) uses a different diagnostic and clears invalid child-span endpoints. Its existence does not establish that it ran in this incident or caused Pbhv's invalidity. `StationAgent` rebinding in the refresh is likewise not evidence that a retained `StationAgent` owned the failing binding.

## Current applicability

The August FUSE incident belongs to a previous game version and is outside the 0.6.x experimental investigation. It is not a current candidate. No further recovery of its old package or versions is required for this ticket. This says nothing about other passenger-stop instances.

The installed native `Railroader_Data/StreamingAssets/AssetPacksCore/nc-bryson-terrain/Data/Map.json`, lines 20650-20670, independently defines industry `ela-house`, component `ela` of kind `PassengerStop`, with `trackSpans` referencing `ela-station`. Its endpoints are `Sp4e8|b|15.36455` and `Sp4e8|a|30.4624`. The file's SHA-256 is `79E157E65BFCAA0B7701C3E3AB8689EC81E8A1F18EF353E63399AA1D1A140C62`. This is native map operations data, distinct from the historical FUSE binding `Pbhv`; the shared place and component names do not establish identity or failure.

The prior local [remaining-applicability analysis](../Issue18/RemainingApplicability.md) records that `IndustryDataLoader.CreatePassengerStop` resolves `PassengerStopDTO.trackSpans` using a span lookup and assigns them to the runtime stop, while `PassengerStop.FindCars` queries the resulting spans and filters stopped passenger cars. The [native capability audit](https://github.com/CrankyAnt/RailroaderScenePatcher/blob/8d3bfc0/Research/NativeCapabilityAudit.md) distinguishes operations DTOs from retained scene components. The definition and static consumer path do not establish successful loading, working passenger gameplay, or a scene-only repair target. The [official map guide](https://docs.railroadergame.com/modding/map-modding/), accessed 2026-11-08, says passenger stops can be defined but are not yet usable in game. No passenger family-wide exclusion follows.
