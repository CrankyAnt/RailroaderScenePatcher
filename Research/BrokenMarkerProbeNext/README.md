# Broken marker warning probe

This separate variant extends the tested broken-marker probe. Its source and binary do not replace the earlier build. Use the same disposable fixture and the protocol in `../BrokenMarkerProbe/README.md`, but install only this probe variant, not both probes. Its arm file is `ARM_BROKEN_MARKER_WARNING_PROBE` and its log is `BrokenMarkerWarningProbe.log`. No game save is permitted.

```powershell
dotnet build Research/BrokenMarkerProbeNext/BrokenMarkerWarningProbe.csproj -p:GameManaged='D:/SteamLibrary/steamapps/common/Railroader/Railroader_Data/Managed' -p:BaseIntermediateOutputPath='C:/TMP/BrokenMarkerWarningProbe18/obj/' -o C:/TMP/BrokenMarkerWarningProbe18/out
```

After every existing repair postcondition and snapshot succeeds, the probe inspects the active native message collector. It refuses a fallback collector. A single active message with key `M5pp` must match warning severity, source `System`, originator `Whistle Sign E`, and the native formatted description for Shuo and the original distance. No match or ambiguity leaves all messages unchanged. For an exact match it calls the native collector's single-message removal method, then records whether the selected object disappeared and every other original message object remains. It does not clear historical game logs. With the optional empty `INCLUDE_WARNING_CONTROL` file in the mod directory, the probe adds one clearly labeled authored warning after a successful repair, collector check and exact match. It records the control object identity and checks that it remains after removal. The probe leaves the control in place until the disposable session ends. Without the control, if no unrelated messages exist, their retention remains untested.

With the game stopped, install the reviewed variant into the disposable profile. Run a dry preflight without the arm file and capture the native warning. Exit without saving. Create the empty arm file, restart and load the same disposable map. For the selective-removal control, create the empty `INCLUDE_WARNING_CONTROL` file with the game stopped. Capture the probe log and native warning UI before and after the repair as timing allows. Record the presence of unrelated messages, if any. Exit without saving, remove the arm file and repeat in a fresh process only as required by the research protocol. A warning that appears and is then removed is distinct from a warning prevented before creation. The native diagnostic API is experimental evidence, not a supported mod contract.

After the armed repair and successful exact warning removal, the on-screen `Restore original broken reference` button becomes available. It is a one-shot action in the current world. The probe verifies the same map, graph, marker, replacement binding, one registration, fixed origin, and baseline hierarchy pose and activity. It disables the component, writes an independent copy of the original serialized fields, invalidates the native position cache, and re-enables the component. It then checks the original unresolved binding, zero registrations, unchanged hierarchy, the returned exact native warning and retained unrelated message objects. A failed guard or postcondition stops the action and requires leaving without saving. The probe does not automatically reapply repair in that world; a later world load starts a new attempt.

Direct serialized field assignment bypasses the native location setter's change event. Cache presence and the separate invalid-position warning flag are logged, but their original values are not restored. This tests the named marker and collector only; it does not establish restoration of dependent subscribers or cached external state.
For this research variant, preflight and repair wait at least 10 seconds after world load and require 5 continuous seconds in which the sampled origin stays within 0.01 world units of the current stability reference. Each observed shift resets the stability interval. The existing 60-second readiness timeout still applies, and the probe logs sampled changes and the final origin and elapsed times. These intervals are an experiment, not proof of a native readiness signal or of stability after capture. A later origin shift still makes the restore guard refuse the action. Earlier lifecycle hooks remain untested.
