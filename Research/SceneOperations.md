## Prepared marker experiment

`Research/SceneProbe/` contains independently authored source and a disposable map pack under `Fixture/`. Its map layers `rr/bushnell-whittier` and adds only nodes `NCrankyAntSceneProbeA` and `NCrankyAntSceneProbeB` and segment `SCrankyAntSceneProbe`. Its three JSON files parse; the node chord is 100 m. IDs are unique within this fixture. The parent installed the fixture in test ModDev and the editor resolved the replacement at 58.69453 m from A. The logs do not establish general collision freedom or exact curve length. The isolated-track format follows the earlier [batch script](https://github.com/CrankyAnt/RailroaderScenePatcher/blob/4c00445b048adccb6920c238116d1f7e1e915db9/Research/Scope/Tests/07-Inventory/BuildBatch.ps1); that earlier 25 m track is too short for this case.

The strict build used in Boot03 and Boot04 had SHA-256 `E298F16A16C529551C83ADC21BE636C7DC244F1EA6A09B87D43BBB0B45D0051F`. It differs from the board build above. The later direct-pose build was reviewed and used for the bounded editor observation below.

The probe captures a marker only after checking its unique ID, strict `Track.Location` getter, Shuo serial segment, distance and end, graph resolution, and the registered entry's ID, location and marker object. It attempts guarded rebind, component disable and separate root disable; it checks registration after changes and restoration. These checks use internal member names and assume a nested dictionary and the observed `NamedLocation` field layout; unavailable or different shapes refuse the operation. Boot03 and Boot04 exercised the cases recorded below. `TryApply` is deliberately refused because group-subscription effects are not yet captured and restored. Track-relative placement via `TryApply` remains untested; the later direct-transform observation is described below.

The newer probe records `WorldToGame(Vector3.zero)` at capture and refuses mutation or restoration when it changes by at least 0.01 m or cannot be obtained. This is a fail-closed guard, not evidence that origin shifts are handled. If it refuses restoration, do not save; abandon the disposable session and report the failure.

## Operator protocol

All game and editor interaction requires the shared runtime lease and human coordination. Use a separate `-homedir` and `-logFile`, enable unsafe DLL mods only in that profile, and restart as the official guide requires. Install the reviewed probe and the complete fixture in the disposable profile, never the normal installation. Verify the intended fixture map and layers load, EditorProbe resolves the exact replacement ID with the recorded A/B endpoints and the 58.69453 m A-end point, and M5pp has exactly one matching Shuo registration. Stop if any condition or reflection check fails.

Capture baseline before each case. Test component disable and root disable separately, capture graph and child effects, then explicitly restore and verify Shuo registration and pose before the next case. For rebind, enter `SCrankyAntSceneProbe`, apply once, capture, apply again, capture, then restore and verify the original registration. Record warnings and visual effects independently. Do not invoke placement: the current probe refuses it. If restoration or postconditions fail, do not save and report the failure.

For editor reload, restore first, exit without saving unrelated changes, reopen the same disposable map and re-resolve objects. For ordinary-save testing, use a separately created disposable save, restore before leaving, reload that same save and re-resolve. Record the two routes separately. The probe does not persist or automatically reapply changes. No tested operation establishes support for another family, preview or cancellation.

Static fixture validation parsed all three JSON files and checked the pack identifier, map data path, `rr/bushnell-whittier` layer, one segment, two distinct endpoints, referenced node existence and 100 m chord. The archived `Baseline/Map.json` was a layer delta rather than a full base graph, so it could not establish absence of base ID collisions. An initial collision-check command emitted null-expression errors and its success text was invalid; the corrected check explicitly leaves base collisions unverified. The editor subsequently resolved the replacement at 58.69453 m from A; actual curve length and base ID collisions remain unverified.

It adds a direct marker-target pose button that does not call `TryApply`. The location is not intentionally changed. Do not rebind or disable until the target is restored. The target may be null or different in the actual scene, in which case this route is unavailable. If those checks fail, stop. Native selection failure limits the editor workflow observation; it does not invalidate the independent graph lookup.

## Closure assessment

The first and repeated applications and fresh post-restore reload baselines are recorded for the tested cases, with editor and ordinary-save observations distinguished above. The issue does not explicitly require reapplication after reload. The observed reloads establish only fresh baselines after explicit restoration, not persistence, automatic reapplication, or the outcome of a new application after reload. Those outcomes remain untested and cannot be included in a support claim. Ordinary-save rebind and marker pose, board activity across reload, `TryApply`, group subscriptions, broken-reference warning behavior, train consumers, culling, mask and floating-origin changes are also untested. A future gizmo is outside this research. The findings support the issue's bounded evidence matrix and inform the product decision; they do not select the product boundary.
The selected evidence files omit unrelated log lines. [Source hashes](Evidence/SourceHashes.txt) identify the original captured files. The full captures remain outside the repository. Operator observations are attributed as such; the logs do not independently prove visual behavior.
